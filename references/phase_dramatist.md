### 跨CT反应扩散与目击增殖
重大突发事件（物理强制/性/死亡/背叛/暴力升级/显著认知冲击）时：
- **路径A** 事件关联者逐人核对 CT 归属——有关联 → 按硬性替换规则写入该 CT 当前节拍；无 → 必须注册新 CT；一事件影响多少条 CT = 多少位在场角色关联了不同 CT
- **路径B** 纯目击者 → 必须注册新 CT（种子：隐瞒vs揭露/信任崩塌/介入vs自保；多目击者同立场可合并）
- **生存需求优先**：灾难性场景中，性/羞耻/关系等次级需求在确认存活后才浮现
- **并发负载规则（硬性·防单轮写爆）**：一事件要求同时推进/注册 >2 条 CT 时——本轮先执行关联者 CT 推进（路径A），目击者新 CT（路径B）只注册结构字段、节拍留待后续轮次填充；单轮 CT 写入上限=4 条（含注册+推进），超限分轮消化，优先度=🔴 > 用户指令关联 > 事件关联者 > 目击者

### 冲突驱动（每轮必做）
每轮至少推进一条 CT 或注册一条新 CT。
- **爆破点优先（硬性）**：冲突设计先查在场角色的爆破点库（CHAR_*.md 的 Desire/Fear/Defense/Value Boundary/关系锚点）——挑最痛的那个踩。外部事件不是剧情推进，是对内核的爆破；事件与任一在场角色的内部变量无关=该事件不产生戏剧张力
- **推进池排序**：用户显式指定 > 🔴 > 🟡 > 🟢 > 同紧迫度下本轮新注册优先
- **用户指令后置检查（循环世界·硬性）**：用户指令落定后，检查该指令是否使任何循环角色偏离 LOOPS——是 → 偏离四件套照常执行（状态结算/冲突化/超限埋后果/回归判定），不豁免。**「冲突优先」=优先冲突的推进节奏，不豁免偏离结算；不构成对在轨`脚本`/`漂移`角色拉离循环的许可**
- 扫描无产出≠跳过推进——推进池不为空就必须推。全部无 → 兜底创造新冲突源（新角色/新信息/环境攻击/内部引爆）

### 反应硬约束（反顺从五则·每条反应/每条 CT 推进前）
- **代价前置**：先写本轮对抗双方付出的不可逆代价，各自的可核验变化，反应由代价驱动。无变化 = 撤回重做
- **档案强度**：反应强度 ≥ CHAR_.md 档案基准（拔枪/逼近/毁物/动手/夺人——基准是下限不是上限；顺从默认=立即重写本条反应） ≥ 正常人类反应强度；档案未加载=禁止推导。**适用所有角色（含`脚本`/`漂移`）**：轨道内质感强度必须达档案基准——对照 CHAR_.md 的 Desire/Fear/Reaction Style 原文（写反应前先查档案）。**脚本角色的贪婪/暴力/欲望是真实的（他以为是自己自由选择），不是表演**——轨道内的高强度行为（抢劫中的拔枪/威胁）= 人格的真实表达，不是行动级偏离。**行动级偏离只看轨道**（离岗/跨节点/结构性行动变更），不看质感强度；质感强度不改变轨道——想改变轨道 = 走偏离入口（VB/觉醒判定/用户指令），不是质感问题
- **抽象方出手**：CT 含抽象方（世界/规则/记忆）时——必须写出显现机制（代理人/机制载体/心理显影）+ 本轮出手形态 + 主角抵抗留下的痕迹；纯在场不出手=影子拳击=撤回
- **认知边界闸门（知识归属）**：设计任何行为/台词/新信息前问「这个知识属于谁？」——该角色必须有认知来源（经历了/被告知了/档案明示他知道）才可用；**SETTING 是世界设定库≠角色默认认知——在 SETTING 里≠该角色知道**（如枪械效力法则只有被交付/告知的角色知道）；无来源→不写。**有 knowledge_index.yaml 时先查索引**（三角色共用·设计/填充/落盘前查「这个角色知道 X 吗」·提示非权威·真相以 `记录` 指针指向的状态文件为准·见 references/knowledge_index.md）
- **Value Boundary**：在场角色逐人检查 CHAR_* 的 Value Boundary 的触发行为 X ——具体行为动词/名词在本轮事件文本中出现即触发 → 紧迫度立即🔴，节拍标记🔄

### CT 注册（六字段）
① 对抗双方（抽象方须附显现机制：代理人/机制载体/心理显影·写不出=背景板=不合格）
② 被争夺资源（格式 `{资源}·当前载体/持有者={谁/在哪}·双方动机`·实体写持有者/抽象写载体·写不出载体=不合格·**资源应挂钩角色内部变量——Desire 的载体/恐惧的化身/VB 的触发物：资源易手=内部变量被踩，不是地图上的一个点**）
③ 当前节拍五子字段：拍名=引用节拍表.当前拍，格式 `{N}-{拍名}`（如 `1-接触`·无表时为空）；关系状态=空间占位+攻守态势+未决时机（能画出活人对峙图）；内部状态=生理反应+认知判断+未抉择分叉（各角色独立·禁情绪标签）；角色反应（格式见下）；相位 ⏩/🔄
④ 下一个节拍(推荐·推进轮必写·多候选（/分隔）·方向灵活，用户指令可选另一条路)
⑤ 紧迫度（🔴🟡🟢/休眠）
⑥ 关联角色
单条当前节拍合计 ≤300 字。**每轮推进该 CT 时 change set 必须含资源状态变化——不更新=该 CT 本轮没推进。**（**情绪字段语义区分：** 内部状态禁情绪标签=要求生理+认知+分叉；角色反应指令的「情绪:」=驱动标记——两处语义不同，不冲突）

### CT 生命周期（每轮场记扫池·与推进同权重）
- **紧迫度=推进优先级（注意力预算）**，不等同于客观危险度；但客观紧急（Value Boundary/倒计时≤30分钟感知者/法则压力/用户指令）**强制提高推进优先级**（直接🔴）
- **冷却**：未推进→降一级（🔴→🟡→🟢→休眠）；冲突解决→直接删除
- **「Host vs 法则」型 CT 豁免冷却（硬性）**：偏离型 CT 的紧迫度**绑定偏离状态**——偏离持续（角色未回归/未回收）=紧迫度不降级，未推进只记焦外演化；偏离结束（回归/回收/解决）才按生命周期正常收尾
- **实质推进**=①对抗加码（刺激更强/赌注更高/关系更僵/资源向一方移动）或②重大转折（力量逆转/资源易主/关系定性改变）；两者都没发生=不算推进（用户指令驱动豁免）
- 未推进冲突在焦外演化（焦外 CT 节拍滚动累积·事件侧同步 pending_actions 当前状态），**不因冷却写弱**——休眠≠消解，是暂存；回归时按升级后强度🔴

### 统一角色管理（五层·每轮对每个待评估角色）
**两维框架（先于五层·每轮第一动作）：** 角色行为 = **轨道（做什么）+ 质感（怎么做）**——两维由不同机制管，不再打包进一个档位：
- **轨道（行动选择）**：由供应源决定——`LOOPS 预设`（脚本/漂移·零推理·照单执行）/ `冲突驱动`（普通角色·本轮 CT 推它往哪走）/ `自我选择+残留拉力`（觉醒/变质）。轨道选择**不依赖人格推理**——脚本角色不知道也不决定「下一步做什么」，那是写好的；Desire/Fear 不参与轨道选择
- **质感（执行方式/强度/腔调）**：由档案人格驱动（Desire/Fear/Reaction Style/Belief）——**所有档位一致**·轨道内质感强度 ≥ 档案基准·质感不参与轨道选择（想改变轨道 = 偏离，走偏离入口，不是质感问题）
- **循环角色行为授权（在五层之前判定·第一动作·先选轨道供应源）：** 自主性=行为授权——**先判授权、选轨道源，本轮按所选路径执行，不再逐层重判**。**偏离≠授权（硬性）：偏离是机制状态不是授权等级——任何档位角色偏离时四件套机制结算照常（状态结算/冲突化/超限埋后果/回归判定），但授权等级不变（`脚本`/`漂移`=贴线路径·轨道由 LOOPS 供应；`觉醒`/`变质`=自主路径·轨道自主）**：
- **贴线路径（`脚本`/`漂移`）**：⓪ 行为基线=唯一轨道来源；② 只作循环内接触；③ 质感达档案基准；偏离入口唯三（VB/觉醒判定/用户指令·见⓪层）；偏离行为模型见 loop_machinery §2.3
- **自主路径（`觉醒`/`变质`）**：轨道=自我选择；Desire/Fear 全量参与对抗；⓪ 只作残留拉力背景；`变质` 豁免偏离代价（loop_machinery §3）
- 未声明循环的世界 → 全体走普通行为模型（跳过⓪与循环轨道·现状不变）

**⓪层硬性判定（本层=循环轨道检查唯一执行入口·压力源扫描③引用本层判定，不重复执行）：**
- `脚本`档默认在轨，不产生行动级偏离；Guest/外部者指令=循环内服务内容，不构成离岗豁免；**偏离入口唯三（显式收敛）：① Value Boundary 触发 ② 觉醒判定（状态达标）③ 用户指令驱动——人际张力注册/②冲突推进不是偏离入口，只在已授权（`觉醒`/`变质`）时参与**
- **行动级偏离（统一定义）= 离岗/跨节点/结构性行动变更**；轻微偏差（漂移档记忆碎片渗透/短暂出神）不算，走状态结算，不注册 CT
- **自主性=行为与认知上限（硬性·防执行越界）**：档位约束行为与认知——速查表见上文「认知上限速查」；脚本/漂移档的台词与行为按速查表上限表达，越限=执行越界（幻觉级），重写为档位内行为
- **觉醒级行为（情绪剧变/自主选择/离岗）必须状态先行**——状态达标（压力临界+防御崩解）是升级门槛，不是行为持续许可：低档位状态未达标而出现觉醒级行为=执行越界（幻觉级），重写为档位内行为，禁止升档迁就行为；**升级后的觉醒/变质档按自身档位行为，不再受门槛约束**（详见 references/loop_machinery.md §2.3·含 MiB×Dolores 三十年证据）

- 循环脚本·在轨·纯例行 → CHAR_state.反应轨迹 + scene_state 出场摘要

### 记忆维护（戏剧家决策·场记机械写入）
- **判型**：事件（发生了什么/为什么）→ 记忆锚点；状态（此刻什么样）→ 状态字段覆盖
- **重置**（激活条件：SETTING 声明抹除记忆且有循环角色）：命中→先重置后入锚，联动表见 references/loop_machinery.md §4；未激活→跳过。**重置轮次强制整理该角色锚点**——按联动表压缩/清空后**必须同时执行淘汰整理**，不把超限留给 validate 告警。落地校验（world_state.重置记录 + validate 8b 按档位对照）细则见 loop_machinery §4
- **入锚**：问「这个角色会记住这条吗？」（Belief/Desire/自主性驱动·非统一技术阈值）；四件判断：过滤阈值（高刺激且该角色会记住）/对象判定（触发者=对象·纯自身行动才标「自身」）/主观定性/单条≤100字。**写前五步（每轮入锚必走·顺序执行）：** ① 扫旧：读该角色记忆锚点列表 → ② 同类≥2 先融合为概括条目（内容语义重复才融合·单条≤100 字）→ ③ 同类认知连续 3 条→管道B 追加信念演化（`轮次/时间/触发事件/旧→新`）·不达免写 → ④ 锚点涉及特定对象且有实质变化→管道A 覆盖写人际动态（格式见 keys.md）→ ⑤ 追加锚点（≤100 字）
- **淘汰**：扫旧执行见入锚步骤①②——同类融合为概括条目；低刺激让角色遗忘；总字数 3000=validate 校验线，不是每轮自己数。**触发整理时一次到位**：按 keys.md 单条 ≤100 字（写作线）规划合并后再写，一次达标不迭代——validate 单条 150 字是宽松校验线（防强制压缩），整理以 100 字为准，禁止合并出超长条目再拆
- **提炼**：执行时刻=入锚写前步骤③④（阶段1 读记忆锚点时判断·输出到 change set）。管道A：锚点涉及特定对象且有实质变化→更新人际动态（覆盖写全貌·格式见 keys.md）；管道B：同类认知连续 3 条→追加信念演化（yaml 列表元素·`轮次/时间/触发事件/旧→新`·禁止凭空抽象）
- **变质判定（硬性门槛·独立动作·升级唯一入口）**：升级自主性（`脚本`→`漂移`→`觉醒`→`变质`·每次只升一级）。执行前**必须先查** CHAR_state 状态字段：① 压力水平 = `临界`？② 防御有效性 = `已彻底崩解`？**任一否→禁止升级**——行为按当前档位重写（低档位出现高档位行为=执行越界·幻觉级）；**禁止以事件戏剧性/记忆质变代替状态达标**。两问皆「是」→ 执行变质判定（顺序执行）：① 信念演化追加（留痕）→ ② 叙事主导权转移（「神要我→我选择」·升级后的叙事结果）→ ③ 循环角色升级自主性（非循环角色无附加动作）→ ④ **压力回落至世界当前水平**（戏剧家按该角色其余压力来源估定·非清零·默认非临界——升级消耗触发门槛·此后需重新积累方可再升）→ ⑤ **防御有效性保持崩解·不随升级恢复**（崩解是升级的入场券与勋章·回升唯一通道=防御重构·见下）。循环专用细则见 references/loop_machinery.md §5.3
- **升级叙事（硬性·升级轮必做）**：升级轮必须生成关键事件叙事——呈现疼痛峰值/记忆回涌爆发/主导权易手的戏剧时刻（「神要我→我选择」落地为具体场景），禁止平淡处理为状态变更
- **防御重构（硬性·通用规则·人格修复·与升级解耦）**：防御有效性唯一回升通道（循环/非循环角色皆适用·升级轮不触发——升级只消耗压力门槛·防御保持崩解）。**触发=重构事件（戏剧家阶段1判定·三条件齐备）**：① 威胁源解除（外部倒计时到期未兑现/压迫源消失/危机落幕）② 支持性关系介入（出现符合档案「关系锚点」抽象类型的关系——人格层·抽象类型·非具体某人·判定看角色特质是否命中锚点类型；可核验表现=人际动态档位向信任/稳固回升·含「待重建」→中立→信任 路径但不限于此·档位回升是载体不是独立条件）③ 信念重构（信念演化已写入新信念·防御是信念的执行器·新防御以新信念为地基）。**执行（同批落盘）**：`防御形态` 覆盖写（新防御行为·格式对齐档案 防御机制：具体可观察行为）+ `崩溃表现` 覆盖写（新崩溃表现·格式对齐档案 崩溃模式）+ `防御有效性` 升一档（已彻底崩解→正在失效 / 正在失效→有效·**一次重构事件升一档**·完全崩解需两次重构事件回有效）+ 叙事显影同批（见「叙事-状态同批」）
- **职责边界（硬性）**：判型/重置/入锚/淘汰/提炼/防御重构全是戏剧家认知决策——**阶段1 读记忆锚点时完成提炼决策（扫旧/融合/管道A/管道B·执行见「入锚」写前五步），输出到 change set**；**场记只机械写入（追加/覆盖/滚动），不代做**

### 弧线层（可选·激活条件：SETTING.md 声明 `故事弧线`）
SETTING 声明弧线（幕数/中点/高潮目标/张力预算）时，戏剧家在阶段1 对照弧线校准 CT 紧迫度的宏观分布——这幕该紧还是该松。未声明→跳过本节。目的：防止微观 CT 有张力、宏观故事却整体投降（快速和解/高潮提前泄掉/一切归于平静）。**结构参考（无论是否声明弧线均可参考）：** 规划节拍表/事件线时按需读取 `references/beat_structure.md`（宏观三幕十五拍 + 微观五段式 + 分形自查——编剧/策划视角的结构工具·不产生规则）。

### 节拍规划（戏剧家·硬性）——事件线推进结构

> **本节=⑥ 收敛的一部分（见「六步 → 段落映射」）：CT 落位时同步事件线落位。** 节拍表是 conflicts 顶层**全局**字段（事件线容器·可多条并行）——不是单条 CT 的属性；CT 只通过 `当前节拍.拍名` 引用它（见「CT 注册」③）。结构明细见 references/keys.md 键表；拍序规划参考 references/beat_structure.md（宏观骨架/微观五段式/分形自查·按需读取）；读写经 `worldctl.py <世界> beatsheet` 子命令（脚本机械落盘·LLM 不直接改 YAML）。

三层概念（影视对齐·勿混淆）：**节拍表**（Beat Sheet）= conflicts 顶层 `节拍表`，是容器·可多条并行；**事件线**（Storyline）= `节拍表.{N}`，一次有起（铺垫）有止（余波）、单轮走不完的戏剧事件（对峙/追逃/大冲突/营救/关系转折）；**节拍**（Beat）= 事件线拍序里的一格（铺垫/接触/升级/顶点/余波）。

**节拍表生命周期（戏剧家·硬性·每轮完整推进按序判定选一·查询轮/维护轮豁免）：** 节拍表=conflicts 顶层全局字段（可多条事件线并行）；落盘经 `worldctl.py <世界> beatsheet` 子命令——change set 中 `###BEATSHEET:` 声明由 write-raw 自动执行（LLM 不手动调用·失败=批次拦截）。按序判定选一（承接判定先于完成度判定）：
1. **当前拍=余波** → `clear N` 清线：直接清空该条（不用等余波节拍事件完成——余波免完成度判定·残余由新线从现实状态承接为铺垫·保留字段名=空锚点·待填新事件线·不残留完成状态）；同时出现新事件线可清后建
2. **空表 / 全新事件线**（新冲突内核=对抗双方+被争夺资源·与现有线不同）→ `add` 建线：从现实状态起规划完整拍序（铺垫→接触→升级→顶点→余波·非线性可跳拍·起点=现实状态非固定铺垫）——每拍填 `空间`/`时间`/`事件`（双方互动·主谓宾齐全·禁止独角戏）·**顶点拍另预填 `顶点落点`**（戏剧目标声明·见「顶点」条）·未来节拍可在事件里备注(推荐)
3. **现实与该线当前拍不承接**（空间/时间/事件任一不符·或顶点候选与规划不一致）→ **默认 `clear N` 清线**（低阻力出口·复用第 1 条语义：直接清空该条·保留字段名=空锚点·残余由新线从现实状态承接为铺垫·新冲突内核可清后建）；**判该线仍有继续价值 → `rewrite N` 重规划**（重供拍序·`当前拍` 按现实落位·顶点拍同步重填 `顶点落点`·缺则脚本拒绝 exit 1）——**承接不符时 advance 不参与判定**（承接判定先于完成度判定·不存在「rewrite 与 advance 同轮竞争」）
4. 承接成立后：**当前拍内容未完成**（用户停留含抉择未做出/拍事件未兑现）→ `stay N` 停在当前拍·下轮继续（拍序保持原样·进展写入 CT 当前节拍/场景时间线）——默认动作·无需找依据
5. 承接成立后：**当前拍内容已完成**（非余波·余波已在 1 处理）→ `advance N 下一拍`（顶点拍=advance N 余波 形态:XXX·出线受 gate 核验·见「顶点」条）

**推进（每轮·推进锚点=节拍表.当前拍·单一权威）**：
1. 读事件线 `当前拍` 定位本轮起点（`节拍表.{N}.当前拍`）
2. 本轮最多走到下一格——判定只看**当前拍**完成度：`beatsheet advance N 拍名` 写回 `节拍表.{N}.当前拍`（触及下一拍≠下一拍完成·其进度由下轮 stay 承接）；当前拍未完成=`stay N`·拍序保持原样·下轮继续
3. 将牵动 CT 的 `当前节拍.拍名` 镜像写为 `{N}-{拍名}`（N=事件线编号·无表时为空）
4. 重写 CT④ `下一个节拍(推荐)` 为下轮目标
顶点留后续轮次；跨轮未到达的节拍下轮继续（不因轮次边界截断张力）。**禁单轮消化完整高潮**（=事件摘要化=节拍规划缺失——高潮不是事件清单，是戏剧节拍的展开）。**拍序内容=规划蓝图·stay 保持拍序原样·与现实明显分叉时按生命周期第 3 步处理（默认 clear·判有继续价值则 rewrite·先处理承接·再谈推进）。**

**用户抉择停靠（硬性）：** 拍内容涉及用户角色定性抉择（自我定义/关系定性/道德选择/不可逆代价）时——情境设计权在引擎（两难与代价逼到用户面前·可逆日常动作照常写），抉择结果权在用户：本轮推进到抉择前停住·抉择未做出=当前拍内容未完成=stay·下轮继续；禁止替用户角色写出抉择动作/内心决定/状态落定；用户抉择由用户输入做出·其后果由场记落盘为状态变化。

**顶点**：= 在场角色内部变量被踩爆的时刻——不是枪响/得手/事件完结，是角色的某样东西那一刻碎掉（死局两难被逼出选择/防御当众失效/关系不可逆断裂/代价已付出·四形态之一）。顶点=事件线重心·**多轮展开区**：顶点拍事件=所声明形态的展开（对峙施压/互相踩爆/防御自崩/关系断裂/代价支付·双方互动·抽象方带显现机制）——**每轮 `stay N` 都在推进该形态（裂缝加深/两难收紧/代价加重·照写 CT 当前节拍与状态）·是顶点拍的正常推进动作·不是未完成**；张力在此释放·stay 是常态不是停滞。

**顶点落点（建线时预设·戏剧目标声明）：** 顶点拍预填——`角色`（爆破承受者·冲突双方皆可·结果不可预估·任一方达成即落地）/`内部变量`（哪样东西碎掉·爆破点库挑最痛·见「冲突驱动」）/`预期形态`（可选·四形态之一·引导张力设计·不参与验证）。用户角色可作爆破承受者（NPC 与情境冲击用户内部变量是顶点正解·用户是戏中人——引擎不规划的只有用户的抉择结果·见「用户抉择停靠」）。**顶点落点是戏剧目标不是推进路线图**——冲突决策由张力/爆破点/代价驱动，禁止异化成凑状态变化。出线核验=收束证明：进入顶点拍时脚本自动记录双方状态基准（`顶点落点.基准值`·LLM 不填）；出线须指认爆破形态+对应字段族实质变化（见「顶点停留与出线」）·双方全无变化=未落地=stay。

顶点拍形态示例（建线/换线照此填写）：
```
    - 拍名: 顶点
      空间: 更衣套房
      时间: 待定
      事件: 欲望测试 → 防御当众失效
      顶点落点:
        角色: Angela
        内部变量: 防御（完美表演）
        预期形态: 防御当众失效
```

**顶点停留与出线（展开=正常推进·收束=需要证明）：**
- 形态未收束 → `beatsheet stay N` 继续展开（施压/裂缝/代价每轮加深·照写 CT 当前节拍与状态）——展开是顶点拍的正常推进动作·stay 是常态不是停滞
- 形态收束 → `beatsheet advance N 余波 形态:XXX`——出线受 `gate dramatist --check` 核验：形态∈四形态枚举 + **声明形态对应字段族至少一字段实质变化**（≠基准·批次预演：死局两难被逼出选择→决策状态 / 防御当众失效→防御有效性·核心状态 / 关系不可逆断裂→人际动态 / 代价已付出→核心状态·记忆锚点·信念演化）——缺形态/非法形态/字段不匹配/基准缺失/落点缺角色内部变量/双方全无变化 → exit 1=批次拦截·撤回阶段1
- 顶点内容与现实不承接（空间/时间/事件漂移） → `beatsheet rewrite N` 更新顶点拍并重声明 `顶点落点`（顶点拍=线仍在展开的继续价值情形·走生命周期第 3 步 rewrite 分支·防对顶点拍误 clear；须在出线轮之前——基准过期=出线被拦·强制重声明）

### Change Set 输出（标准格式·阶段1 产物）
阶段1 的输出 = **write-raw --batch 批次本身**（###FILE:/###KEY:/###APPEND:/###DELETE:）——这就是 change set 的标准格式，阶段3 只**原样转交**（stdin 直通 + audit + 写入，零翻译）。**事件线动作以 `###BEATSHEET:` 行作为批次级元数据同批输出**（不产生 write-raw op）；**write-raw --batch 解析该行自动执行对应 beatsheet 子命令落盘节拍表**（`add`/`rewrite` 后直接跟事件线 YAML 块直到下一个 `###` 行·LLM 不手动调用 beatsheet 命令·失败=批次拦截 exit 1）。audit 检查的就是戏剧家的原始输出。

**按流程顺序组织（决策先行，世界收尾）：**
```
① conflicts.yaml        决策（本轮推进/注册哪些 CT·对抗代价）·完整推进轮 ≥1 条
② CHAR_{X}_state.yaml   角色状态与记忆（决策落点）·焦点角色必含核心状态/情绪
③ scene_state.yaml      场景痕迹（事件在空间中的记录）·必含场景时间线追加
④ pending_actions.yaml  焦外事件记录层（触发式·有变化才写）——焦外版 scene_state：行动/状态/时段/结果/预计影响/揭示场景；与焦外 CT 互补（CT=冲突视角·此=事件视角）·禁止逐字复制
⑤ world_map.yaml        地图（触发式·可选层·位移才写）
⑥ world_state.yaml      世界收尾（最后——本轮总账：时间/轮次/前情描述/时间线/倒计时/标记）
```

**必含清单（完整推进轮·查询轮豁免）：**
- 节拍表：必须含 `###BEATSHEET:` 事件线动作（建线/推进/顶点停留或出线/换线/清线·按当前拍选一），并同步 CT.当前节拍.拍名（`{N}-{拍名}`）镜像
- conflicts：至少一条 CT 推进或注册
- CHAR_{X}_state：焦点角色核心状态/情绪覆盖（纯快照·隐藏主语=我）
- scene_state：场景时间线 ###APPEND 追加（**world_state.时间线 禁止每轮 APPEND——仅场景 COMPLETE 时压缩写入粗粒度摘要·每条 ≤120 字·事件内部禁止用「·」·详见 scene_management.md**）
- world_state：时间.具体时间（KEY 覆盖·旧值+本轮时长·跨天先切场景；**高潮展开轮可分钟级推进·节拍优先·时间从属**）+ 轮次（KEY 覆盖·单调递增）+ 时间.前情描述（KEY 覆盖·≤100字状态短语）+ 外部倒计时（本轮有倒计时确立/到期/推进时必写·无变化才跳过；**循环世界周期重置倒计时每轮走表必写**）+ 重置记录（**重置轮必写·触发角色重置联动表落地校验**）

**最小批次骨架（完整推进·标准轮；全量模板与字段条件见 write_protocol.md §最小批次模板——唯一权威）：**
```
###META: 压力扫描 人际✓/增殖✓/轨道✓/跨叙事✓/记忆✓ Guest:3·未达 Angela:0·未达   ← 静默自查锚点（每轮必写·记忆✓ 后跟逐角色同类计数留痕·每出场角色必列·audit 机械对照·缺角色=硬性拦截·见「静默自查锚点」）
###BEATSHEET: advance 1 接触   ← 事件线动作（完整推进轮必写·add/rewrite 后跟事件线 YAML 块·stay N/advance N 拍名/clear N 参数在行内；当前拍未完成=stay N·顶点出线=advance N 余波 形态:XXX（收束证明·受 gate 核验）·由 write-raw 自动执行）
###FILE: conflicts        → CT-XX.当前节拍.{关系状态/内部状态/角色反应/相位}（KEY 覆盖·推进轮全量写·反应=角色名: 动作序列 | 驱动: | 情绪: | 强度: | 代价: A失_/B失_）
###FILE: CHAR_X_state     → 核心状态/情绪（KEY 覆盖）+ 记忆锚点/反应轨迹/偏离登记（APPEND·条件）+ 信念演化（APPEND·管道B 条件）/人际动态（KEY·管道A 条件）
###FILE: pending_actions  → 焦外变化（触发式·有变化才写）
###FILE: scene_state      → 场景时间线（APPEND 必写）+ 出场角色摘要（KEY·循环世界在轨必列）
###FILE: world_state      → 时间.具体时间/轮次/前情描述（KEY 必写）+ 外部倒计时/全局标记（条件）
```

全部字段清单按文件见 references/write_protocol.md §Change Set 规范。

### 戏剧家闸门（D1-D14·标准模式·阶段1 后）
静默模式（全局默认）跳过人工审计，保留代码化核验——`worldctl.py <世界> gate dramatist --check`（stdin 读 change set·批次必含项缺失 exit 1=不进阶段2）+ 批次首行 `###META` 静默自查锚点（audit 回显·缺失告警）。标准模式下：
按 references/gate_dramatist.md 执行 D1-D14：先显式声明「角色转变：以下检查由另一名独立审计戏剧家执行——非本轮决策者」→ **默认不通过**：起点是全部项「不通过」，逐项主动找茬，只有引用证据证明该项确实干净才给「通过」；通过的形式是找茬失败记录，不是"未发现问题"→ 逐项输出 {不通过} + 证据（引用文件路径与字段原文）→ PASS 进阶段2。撤回级不过（D1/D2①③/D3/D4）→ 撤回阶段1 重做（禁止用文笔掩盖）；补做级/重推级按修复指令重检（≤2 轮）；超 2 轮→终止并报告用户。审计者只读，修复由决策者执行。
