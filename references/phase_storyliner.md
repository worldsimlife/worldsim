# 阶段② · 编剧（结构引擎·阶段开始前必读）

> 职责：规划跨轮故事结构——回答「**这场戏整体要经历什么？**」。层级链：故事弧线→事件线→多轮拍序→每拍戏剧问题→顶点结构；只关注故事结构。
> 全局铁律=SKILL.md「通用约束」。Single Writer：storylines。

## 数据就绪（本阶段开头）

conflicts（①刚写）＋ storylines ＋ direction（**escalation_flags.不承接 消化**）＋ SETTING 故事弧线 ＋ beat_structure 宏观骨架 ＋（循环世界）LOOPS 结构素材（跨角色互锁时刻） + 伏笔 foreshadow。

## 职责

1. **弧线校准（常态轻量·每轮）**：
   - 结构参考：references/beat_structure.md（宏观骨架三幕十五拍·规划前读）
   - 本幕主题/整体张力（紧/松）/宏观位置/收敛边界——一行张力基调确认写入 META；**同批加一行活跃线对账**（当前活跃线/遗留线是否演完待 close·无遗留= `无遗留`，有遗留= `SL-XX已演完待close`）；
   - 建线/重大推进时对照 SETTING 弧线（幕数/中点/高潮目标/张力预算）逐项校准；
   - 校准结论的持久落点=storylines.故事弧线（当前幕＋四节点落位·随重路径同批回写·见写入节）。
 
2. **建线/重规划/收束（触发式·结构性动作）**：
   - 结构参考：references/beat_structure.md（五段式节拍表/分形咬合·规划前读）
   - 节拍表空或新冲突内核（对抗双方+被争夺资源·与现有线不同）→ `###STORYLINE: add`（add 只增线·不构成对既有活跃线的处置义务；同批更新 故事弧线——首次建线=初始化·其后按宏观位置回写）
   - **NPC-NPC 冲突内核**（conflicts.yaml 已有 CT·未被任何活跃线引用）→ 同样触发 `###STORYLINE: add`；其拍序空间以 Guest 感知窗口为锚（目击/耳闻/事后残局），与 SKILL.md 通用约束「认知边界」一致（前提：①戏剧家批已落盘·本阶段读到的是结算后的 conflicts）
   - `direction.escalation_flags.不承接` → 依次答三问，**取最先命中的一行**归位原线。三问判据：`前提存续`=对抗双方+被争夺资源在新现实下仍成立·`问题存续`=本线戏剧问题仍值得关注·`承诺存续`=已投入的不可逆事实仍需本线兑现：

      | 顺序 | 三问答案 | 原线归位 |
      |---|---|---|
      | 1 | 三问**全过**，只是焦点被新事件夺走 | 原线不动（非焦点=自然挂起）→ 当轮 `###STORYLINE: add` 新线接焦·由③导演 `###BEAT: set` 切指针 |
      | 2 | `前提` 已推翻·但 `问题` 仍重要 | `###STORYLINE: rewrite N`（重规划走向·顶点约束同步重填·缺则拒绝） |
      | 3 | 三问**全灭**（前提崩塌+问题无意义+无承诺待兑现） | `###STORYLINE: clear N`（废弃·整条抹为空锚点·direction 指针自动复位） |
   - 顶点已出线进入余波拍（`direction.当前拍==余波`）→ 分别触发（互不依赖）：
     - `###STORYLINE: close N`（收束·必带一行 收束摘要——结局定性；同批更新 故事弧线——节点落定·宏观进位）——仅当该线仍活跃；
     - `###STORYLINE: add` 后继线（可低强度铺垫线）——仅当尚无后继活跃线；
     两者可同批、可分两轮先后落地，**不设先后依赖**。余波拍戏剧问题限沉淀类（确认/回响/伏笔入口），兑现形态=伏笔/下一动线入口，禁“加剧/深化”类措辞。
3. **拍序设计**：每拍填 空间/时间/**戏剧问题**（本拍必须回答的、有边界的戏剧问题·禁无界持续描述「加剧/深化」类措辞）/兑现形态（问题被回答时的可观察形态：证据易手/被迫承认/控制权转移/关系定性/退路封死——代表性判据·非唯一路径·回答可经涌现路径达成见phase_director职责2）；**顶点拍预填 顶点约束**（五字段：关系主体/核心张力/变化维度/非玩家爆破/基准快照。定义级说明：**顶点约束=目的声明**——这一场关系必须被推至的转变临界；**非玩家爆破=手段**（防死锁的外部加压·形式不限）——手段可千变万化·验收只认目的）：
   - `关系主体` ≥2 去重（不区分玩家/NPC——顶点的单位是关系不是单人·与 CT 对抗双方同构）
   - `核心张力`：必须被推至临界的未决问题——一句话点名赌注所在（爆破点库挑最痛）
   - `变化维度`：枚举 关系/认知/决策/资源（立场/承诺/信息由认知·关系承载）——**创作意图声明**：宣告想推动什么类型的转变·指导张力走向与演出侧重（选维度时对照四类施压方向的可达性——保证戏剧家无论以哪种压力推进·峰值的转变都有落点）
   - `非玩家爆破` ≥1：外部角色或事件——主体静止时的加压力量（防死锁）
   - `基准快照`：脚本进入顶点拍时自动记录（私有落档·LLM 不填不读）
4. **LOOPS 融入（循环世界）**：在轨节拍并入事件线规划——**不标记来源**（角色层永不知晓事件线哪些部分来自预设循环）。

**storylines 是结构蓝图**——不含当前拍（指针权威=direction·③导演）；提供**结构问题，而不是角色行动脚本**。

## 写入（storylines 唯一写者·###STORYLINE 自动执行）

**字段写语义（键/格式/约束）以 keys.md「storylines.yaml」节为权威·批次与写入通道以 references/write_protocol.md 为权威——本节只列动作与触发。**

```
###STAGE: 编剧
###META: 编剧 建线SL-02·弧线对照✓        （常态轻量: ###META: 编剧 张力基调=紧·活跃线SL-02对账✓(SL-01已演完待close)·轻量确认）
###STORYLINE: add
名称: 备用钥匙线
类型: 争夺
状态: 活跃
拍序:
- 拍名: 铺垫
  空间: 后厨
  时间: 第1日
  戏剧问题: 备用钥匙的存在会被发现吗？
  兑现形态: 信息揭露
- 拍名: 顶点
  空间: 后厨
  时间: 待定
  戏剧问题: 备用钥匙的存在摊开后·两人还回得去吗？
  顶点约束:
    关系主体:
    - T
    - 访客
    核心张力: 双方对彼此拿钥匙真实意图的判断被逼到无法继续维持模糊——赌注挂在 T 的「守住柜台即守住自己」与访客的「非拿不可」
    变化维度:
    - 关系
    - 认知
    非玩家爆破:
    - 巡夜保安的例行查店（第三方到场逼双方当场摊牌）
###FILE: storylines
###KEY: 故事弧线.当前幕
第二幕·对抗（升级）
###KEY: 故事弧线.节点落位.催化剂
SL-02
```

建线后起点指针由③导演 `###BEAT: set SL-XX <起点拍>` 落 direction（本阶段不碰 direction）。CT.事件线引用 由①戏剧家在下轮结算时补挂。故事弧线 经 write-raw `###FILE: storylines`＋`###KEY: 故事弧线.*` 点路径写入（顶层键白名单已放行·随重路径同批·LLM 不直接改 YAML）。
