# WorldSim — 场景管理参考（scene_management.md）

> **场景相关机制全规格。** 场景切换/移动/存档/校验时读取；不逐轮加载。

---

## 注册范围约束

**一个场景只注册当前焦点空间（叙事停驻的连续物理空间）内的锚点、道具、出场角色。** 同一地理区域不同焦点空间 = 不同场景。禁止预注册焦点外元素；锚点不足5个时允许少于5，禁止为凑数超范围注册。

**锚点语义：** 物理锚点=焦点空间内的可视参照物。相邻区域节点可作方位提及（如「北侧是 Mariposa」），但不是可驻留空间——角色进入其内部并停驻即触发下方主判据。

## 类型边界

**焦点空间在 INT（室内）↔ EXT（室外）之间切换时，视为场景边界，触发场景切换流程；** 仅在两类空间之间短暂穿行（过门槛/穿门廊）时走 Waypoint 协议。INT/EXT 按 scene_card 的「类型」字段登记，不因同地理区域而合并。

## 时间区间边界（Scene = Time + Place）

**一场戏 = 同一地点 + 同一时间区间内的连续事件。** 场景切换触发条件 = 物理空间变化 **或** 时间区间跨越，任一即切（电影/剧本行业标准：`INT. MARIPOSA - AFTERNOON` → `INT. MARIPOSA - NIGHT` → `INT. MARIPOSA - NEXT MORNING` 是三个场景——地点没变，时间区间一变就是新场景）。

**时间区间跨越触发（任一满足即切新场景）：**
- **跨天** → **必切·无豁免**。判定只看字段：新 `时间.具体时间` 的日期 ≠ 旧 `时间.基准时间` 的日期。独立于重置执行——跨天即切场景，重置联动表在重置时刻单独执行，互不阻塞。
- **同一天内大区间变化**（午后→夜 / 清晨→正午）→ 建议切。若叙事连续无断点，可在场景时间线注明「时间推进至X」而不切——**本条豁免仅适用于同一天内，跨天不适用**。
- **小时间推进**（13:30→13:45）→ 不切，属场景内正常时间推进。

**基准时间语义（硬性）：** scene_card 的「基准时间」= 该场景叙事的时间锚点。当叙事实际时间偏离基准时间超过一个时间区间（或跨天）→ 触发场景切换流程。禁止把跨天/跨区间的叙事继续挂在旧场景 ID 下。

## 移动场景协议（同一 REGION.md 节点内连续位移）

**主判据（有 regions/ 目录树时·机械接管）：** 焦点角色所在的 REGION.md 节点 ≠ 焦点场景 scene_card「区域」节点 → **即切新场景·无豁免**。`round-check`/`validate` 按此判据机械复核（POV 角色 `位置` vs scene_card `区域`）——FAIL=先执行 §场景切换流程 再继续落盘。目录树缺失或节点无法解析（迷雾制世界）→ 按本节下列既有规则判断。

当焦点角色在**同类型空间**（EXT→EXT 或 INT→INT）内连续位移·移动本身是叙事主体·**且全程在同一 REGION.md 区域节点内**（该节点的连续子空间·无独立 REGION.md——如 Welcome Center 的入境长廊→主厅）时：

1. **场景不强制切换**——位移叙事可挂当前场景 ID：
   - **锚点只注册增量**：新到达的子空间元素才写当前 scene_state 的物理锚点；起点空间元素（已在旧场景注册过的）不重复注册，连续性靠 §场景切换流程第7步「连续性核查」保证
   - 位移路径本身（小径/路口/走廊）可注册为锚点
2. **触发切换（任一满足即切新场景·最简明确标准=移动到不同 REGION.md 区域节点）：**
   - **位移到达另一 REGION.md 区域节点**（如 Train Station → Main Street——区域节点不同=不同焦点空间·**即切**·不因移动协议豁免）
   - 叙事停驻新空间 ≥1 轮且发生核心戏剧冲突（对话/事件/对峙）
   - 新空间需要独立的道具/线索/出场角色注册（或与新区域节点对应）
3. **场景 ID 命名：** 移动场景 ID 应反映终点或全程（如 `S05-镇子边缘·田野·树林`）；若 ID 已注册且位移超出预期范围，允许在场景时间线中注明「位移至新区域」而不改 ID——但**新锚点必须增量注册，不得跨场景重复注册**（此条仅适用同一 REGION.md 节点内的子空间位移）。

## 世界地图协议（world_map.yaml · 迷雾制·可选）

**定位：** world_map.yaml 是**可选增强层**——缺失时 validate 静默跳过、snap.py 自动兼容、叙事照常。有 `regions/` 目录时=**镜像层**：节点/层级/类型/档案从目录树派生（validate 对账自动补全）·**禁止手写节点/指针**；无 regions/ 目录时=迷雾制（初始空·随叙事登记）。

**对账（有 regions/ 目录时·validate 自动·场记零动作）：**
- 结构权威=regions/ 目录树——validate 每轮对账：缺失节点自动补入（类型/档案从档案复制·层级镜像目录树）·多余节点提示（目录树已删）·档案指针悬空警告（文案指向既有候选）
- 场记只补动态字段：`发现于`（新到达节点首次到达场景 ID）·`备注`（≤80字空间事实）——经 `write` 命令（YAML diff 递归合并）

**登记时机（无 regions/ 迷雾制·任一触发即登记）：**
- 场景切换流程第8步（新场景到达未登记区域）
- 移动场景协议：位移到新区域时（增量登记，与锚点增量同步）
- Waypoint 经过新地名且值得记（可省略）

**登记规则（详见 keys.md §world_map.yaml）：**
- **命名：** 镜像制=目录节点名（如 `Sweetwater/Main Street`·不取 SETTING 口语名）；迷雾制=地名优先取 SETTING.md → `## 地理` 的区域名；SETTING 无地理段时按叙事实际命名
- **层级：** 镜像制=镜像目录树（目录树为结构权威）；迷雾制=先找父层节点：新区域属于已登记大区/地点 → 挂到其 `子区域` 下；父层未登记 → 先建父层再挂
- `发现于` 写首次到达的场景短 ID（如 `S02`），validate 逐层递归核对引用
- 每区域 ≤80 字备注；不写叙事，写发现所得的空间事实
- `连接` 写与本节点相邻的可达区域名，可指向**未登记的迷雾区**（地图边缘暗示）

**写入方式：** 登记新区块用 `write`（YAML diff 递归合并，深层路径友好）——Windows PowerShell 下 heredoc 不可用，改 UTF-8 临时文件 + `cmd /c` 重定向（见 commands.md 顶部备注）：

```bash
cat << 'EOF' | python3 {skill_dir}/scripts/worldctl.py {世界名} write
world_map:
  已探索区域:
    甜水镇:
      类型: EXT
      发现于: S01
      子区域:
        主街:
          类型: EXT
          方位: 东西主轴线
          子区域:
            火车站月台:
              类型: EXT
              方位: 主街西端
              发现于: S01
EOF
```

单字段更新（如改备注）同走 `write`（只给目标节点）——**禁止 write-raw/append-raw/delete 点路径**（键名可含空格/点（如 `Westworld Park 1`）·点路径与 shell 分词均不支持·write-raw 已机械拦截；详见 keys.md §world_map）。

## 区域静态档案（regions/ · 可选增强层）

**定位：** 区域静态设定（只读·世界初始设定·人工维护）。与 world_map 的区别：档案 = 设定源（上帝视角·t=0 快照），world_map = 探索进度（动态·从档案派生）。有 `regions/` 目录即激活本增强层；缺失不影响运行。模板：`templates/REGION.md`；键表明细：references/keys.md §区域静态档案。

**目录约定：** 每个节点一个 `{节点名}/REGION.md`——含子区域的节点与叶子节点同一结构（添加子节点 = 直接加子目录，零迁移）。目录名与 world_map 节点名对应；异名时 REGION.md `属性.对应节点` 写明映射。

**静态只读（硬性）：** 档案**永不改**——与 SETTING.md / CONFLICTS_SEED.md 同级（设定·不改）。布局变更（推倒墙/改建）是动态演进 → 写 scene_state + world_state 全局标记/时间线，档案保持初始设定。

**有档案 ≠ 已探索：** 档案预写是设定（同 SETTING.md 预写）；探索/解锁/认知归动态层——world_map 已探索区域按到达点亮，CHAR_state 已知地点 管角色认知。

**world_map 派生登记：** 到达新区域 → 从对应 REGION.md 复制 `类型/方位/连接/子区域` → 附加 `发现于`/解锁状态/动态观察备注。已登记的每一项必须有静态出处；迷雾原则不变（未探索邻居不登记）。

**场景创建物理基线（优先级链·⑤场记）：**
1. `--from` 已有场景（同物理地点切换·继承真实演进状态）→ **优先**
2. 无 `--from` → 当前节点档案（首次到达·初始基线）
3. 两者都无 → 从零注册（现状）

**档案基线生成后（硬性）：** 场记对照 world_state 全局标记/时间线中该区域的**已登记不可逆变更**（如布局破坏）做增量覆盖，再开写——档案=初始，全局标记=演进，覆盖后不会"墙又立起来了"。

**一致性对账（validate 可选）：** 已登记 world_map 节点若有 `档案` → 核对 `类型` 与档案一致 + 指针悬空告警（单向派生对账·软告警）。

## 场景切换流程

> **执行者=⑤场记（硬性）**：本流程全部由场记执行——③导演只输出转场决策（direction.转场），不调用脚本、不创建场景文件；场景内容文件（scene_card/start_snapshot/CHAR_state）由⑤场记参考 templates/ 生成。
>
> **初始场景例外：** 首次启动（无焦点场景）的初始场景创建属**启动序列入场物化**（session_recovery.md 第二章·确定性物化·非本流程）——首轮推进时焦点场景已存在，本流程切换检测不触发。

当叙事焦点的物理空间发生变化 **或时间区间跨越** 时：

1. **场记检测（写入任何文件前必做）：** ①物理检测——当前叙事到达新物理空间（≠ world_state.焦点场景 指向的场景；有 regions/ 目录树时以 REGION.md 节点比对为准：POV `位置` 节点 ≠ scene_card `区域` 节点即命中·round-check 机械复核）；②时间检测——change set 的新 `时间.具体时间` 与旧 `时间.基准时间` 对比：日期变化（跨天）或区间跨越。任一命中即触发本流程，检测先行于 narrative 与状态文件的写入。**不存在「切回已存在场景」——场景 = 地点×时间区间，时间只增不减：回到同一物理地点但时间区间不同仍是新场景（新 ID），第4步创建不可跳过。**（重置由周期倒计时管道机械触发——write-raw audit 拦截 + `reset-cycle`·与场景切换解耦·详见 commands.md）
2. **冻结 + 时间线压缩（硬性·COMPLETE 时做）：** 将当前场景的最终状态写入 scene_state.yaml（如道具被移动）；其 `场景时间线`（细粒度）**当场提炼**为 world_state 时间线中的粗粒度摘要（###KEY: 覆盖 `时间线.{旧场景ID}`，≤3 转折点·每条 ≤120 字·事件内部禁止用「·」）——**压缩主动在 COMPLETE 时执行，不留给 validate 告警**
3. **更新 INDEX.md：** 旧场景状态 → COMPLETED
4. **创建新场景：**
   - 确定场景 ID（SXX，递增）
   - 运行 `init_scene.py`（**脚本只建基础设施：目录/narrative/INDEX ACTIVE/`--from` 继承；不生成内容骨架**）——scene_card、start_snapshot、CHAR_state 由场记参考 templates/ 直接生成完整文件；scene_state 静态基线随剧情轮元素注册自然累积（继承场景由场记按 `--from` 清单 + 当前时间演进填充）（**模板占位（[字段定义]/(例:)）清零后才运行**）
   - 编写 scene_card.md（元数据）→ 模板参考 `templates/scene_card.md`——**「出场角色」/「焦外·在场」两栏不即兴**，由 cast 派生源生成（见第6步）；**「区域」字段必填**（完整路径·对应 regions/ 目录树节点·引擎层）：`init_scene.py --place <路径>` 自动写入；未传 `--place` 时脚本输出候选（从当前焦点场景区域档案的相邻/子区域·或目录树匹配场景名）——**照抄脚本输出·禁止手编路径**
   - 编写 scene_state.yaml（**元素随剧情轮注册自然累积**：物理锚点/道具/核心状态/关键场景信息/出场角色摘要——入场帧已涉及的元素随 change set 正常记录）——**`场景时间线` 创建时留空**（剧情事件一律由每轮 change set `###APPEND:` 追加，创建路径与 change set 双写=重复）；**同物理地点切换（场景名含相同地点词，如 Mariposa-夜→Mariposa-清晨）物理锚点/道具必须继承旧场景清单（`init_scene.py <世界> <ID> <名> --from <旧场景ID>`）——脚本整块继承，同一栋建筑的空间元素不因时间区间变化而消失，锚点清单=--from 继承的旧场景清单；继承场景的道具状态应按当前时间演进（倒了的酒隔几天会干涸——位置一般不变）**
   - 冻结 start_snapshot.md（一次性写入·后续不改）——**内容=角色进入场景那一刻的完整状态（场景叙事第一帧·不是场景进行中/互动后：禁止"已完成互动/已走完流程/道具已被使用"的形态——如"旅客已在吧台喝半杯"是进行中，不是开场），创建后立即填充（禁止留模板占位（[字段定义]/(例:) 残留）运行）**：角色姿态=scene_state 出场角色摘要的开场形态（位置/姿势/正准备做什么），道具位置=scene_state 道具清单的关键项+位置（互动前·未被使用/未被取走）；**开场心理态**（各在场景色的情绪/压力水平/防御有效性——重置后 CHAR_state 恢复开场形态的依据）；**开场 conflicts 节拍态**（哪些 CT 处于哪一拍）；**开场 world_state 附加态**（外部倒计时/全局标记——前情描述不存·可从姿态/核心状态派生）；**焦外待揭示**（pending_actions 中揭示场景=本场景的活跃条目+当前状态——重置后立刻要用·不可重建）；同物理地点切换（--from 继承）时道具位置继承旧场景清单、角色姿态按切换时刻更新 → 模板参考 `templates/start_snapshot.md`（每字段格式/示例/恢复映射见模板）
   - 更新 INDEX.md（新场景 → ACTIVE，展示用——权威源是 world_state.焦点场景）
5. **更新顶层状态：** world_state.yaml **第一行** `焦点场景` → 新场景短 ID（如 `S04`，不含场景名）——**唯一权威源**，漏更会导致后续写入落到旧场景；同时更新 `基准时间`、`具体时间` → 新场景基准时间，`前情提要` → 新场景首轮摘要。INDEX.md 状态列同步标 ACTIVE
6. **检查出场角色（cast 派生 + 物化·硬性）：** cast 派生源 = POV ＋ REGION.常驻NPC ∪ conflicts 关联角色 ∪ direction.焦外角色——`scene_card` 的 `出场角色`(焦内) / `焦外/在场`(焦外) 由此生成（不即兴）——一律写具体角色名（`CHAR_{名}` 具名条目·与 direction.调度单同规）；仅无 CHAR_.md 的纯背景可标群像。遍历 cast 成员：① 缺 CHAR_.md / CHAR_state → 按 scene_state 描述推断补齐；② **CHAR_state 为骨架（未填充·占位符）→ 先按 CHAR_.md 基线 ＋ 当前时刻/LOOPS 位置物化**（位置/核心状态/decision.当前计划），再供④维护；③ 焦外成员 → ⑤ 记 pending_actions（有价值客观事实·可揭示）。**④ 跨场景焦外迁移（防断线）：** 旧场景 pending_actions `活跃中` 条目按 `揭示场景` 归类——① `揭示场景=新场景`（或仍相关·未揭示）→ **迁移到新场景 pending_actions**（保持活跃中）；② `揭示场景=旧场景` → 留旧场景（归档）；③ `已完成` → 保持。**新场景 pending_actions = 旧场景迁移 ∪ 新场景④自推演派生**。
7. **连续性核查：** 旧场景 end_state 的服装/道具/伤口 → 新场景 start 是否一致
8. **world_map 对账（镜像层·validate 自动·场记只补动态字段）：** world_map 节点/层级/类型/档案由 validate 从 regions/ 目录树对账派生（缺失节点自动补入·类型/档案从档案复制）——有 regions/ 目录时**禁止手写节点/指针**；场记只补 `发现于`（新到达节点首次到达场景 ID）与 `备注`（≤80字动态观察）。无 regions/ 目录时走迷雾制登记（见 §世界地图协议）
9. **跨场景轮落盘顺序（硬性·防落点错位）：** ① **旧场景收尾先写**（焦点场景=旧场景）——旧场景收尾条目（scene_state/CHAR_state/conflicts）`###FILE: scene_state` 落在旧场景；**INDEX 旧场景 COMPLETED + world_state 时间线压缩**；旧场景收尾叙事（=发生在旧场景内的本轮 CT 全部节拍）`write_narrative.py <世界> <旧场景ID>` 写入旧场景 narrative.md；② 再 init_scene 创建新场景（焦点切换）；③ **新场景入场帧（焦点已切）**——入场帧元素写入新场景 scene_state；入场帧叙事 `write_narrative.py <世界> <新场景ID>` 写入新场景 narrative.md；④ validate。两段各归其位，禁止合并写入单一场景；**焦点切换后只写新场景条目**（scene_state 落点=焦点场景目录·已重定向）；**输出 = 一条正文按时间顺序合并两段（旧场景收尾 → 新场景入场帧），保持「输出=回合终点」单一性**。**批次拆分（硬性·change set 按落点拆为两个 write-raw 批次各执行一次）：** ① 旧场景收尾批次（焦点=旧场景·只含旧场景条目）→ ② init_scene 创建新场景（焦点切换）→ ③ 新场景入场帧批次（焦点=新场景·只含新场景条目）；**批次按落点拆分执行**——批次落点=焦点场景目录·不拆批则新场景条目全部落进旧场景（scene_state 落点由 write-raw 按当前焦点场景判定·批次内无场景标注机制）。

## 场景重置（回到 start_snapshot 状态）

**触发：** 用户说「重置当前场景」/「/reset-scene [场景ID]」（缺省=当前焦点场景）。

**执行：** `reset_scene.py`——narrative.md 轮转归档为 `narrative.r{轮次}.<时间戳>.md`（保留历史·轮次=被归档 narrative.md 首行或 world_state 顶层轮次·无轮次时纯时间戳），+ 置空；scene_state.yaml 的 `场景时间线` → ''、`核心状态` → 待填充占位；**静态基线保留**（物理锚点/道具/关键场景信息/出场角色摘要——场景物理定义不因重置销毁）；**world_state 时间/轮次回退至场景开场**（start_snapshot「冻结时间」→ `时间.具体时间`/`基准时间`·「开场轮次」→ `轮次`——「时间只增不减」只约束正常推进·显式重置是主动回退例外）。

**重置后（戏剧家必做）：**
1. 读 start_snapshot.md——冻结时间/开场轮次/角色姿态/道具位置/**开场心理态/开场 conflicts 节拍态/开场 world_state 附加态/焦外待揭示** 是恢复依据
2. 重新填充 scene_state.yaml 核心状态（到开场瞬间）
3. **检查 conflicts.yaml / direction**——CT 关系状态/内部状态/相位 是否仍是回退前的状态？按场景开场回退/覆盖 → 对照 snapshot 开场节拍态；direction 当前拍指针一并核对（回退跨拍时按 snapshot 开场态重设）
4. **检查 CHAR_*_state.yaml**——核心状态/情绪/位置是否为开场形态？**累积字段按开场轮次裁剪（硬性·用 snapshot 开场轮次做基准）：记忆锚点/信念演化/偏离登记/连续行动轨迹/场景时间线为 yaml 列表——删除 `轮次 ≥ 开场轮次` 的元素（轮次是元数据字段·直接按字段过滤）**；反应轨迹（旧字段）超窗自动裁（脚本）；外部者角色（如 Guest）必须裁剪未来记忆·Host 可保留作既视感/碎片素材（保留属豁免·默认裁剪）
5. **检查 world_state.yaml**——前情描述（可从姿态/核心状态重写·无需 snapshot）/外部倒计时/全局标记（脚本只回退了时间/轮次·其余仍可能是回退前状态）→ 对照 snapshot 开场附加态
6. **检查 scene_state.yaml**——核心状态/出场角色摘要恢复开场形态（脚本只清了时间线·静态基线保留）→ 对照 snapshot 角色姿态/道具位置
7. **检查 scenes/{当前焦点场景}/pending_actions.yaml**——**揭示场景=本场景的条目按 snapshot 焦外待揭示恢复（含开场状态）；揭示场景=无的纯背景条目清空·按 LOOPS/conflicts/CHAR_state 重新生成**（骨架可重建·不存 snapshot）·world_map.yaml 回退期间新登记区域（如有）
8. 继续叙事（reset_scene.py 输出同样含此清单·脚本不自动处理——快照成本高·由 LLM 判断处理）

**注意：** 重置是场景级操作——CHAR_state（角色记忆/情绪）不因场景重置而清空；角色跨场景连续性照常。若需要角色记忆也重置 → 走 LOOPS 重置机制（循环世界）。

## 过渡空间（Waypoint）协议

角色在两个正式场景之间移动时经过的中间空间。

**何时使用：** 角色穿过连接空间前往另一场景，该空间内不发生核心戏剧冲突，目的是「到达」而非「停留」。

**规则：**
1. **不需要**创建 scene_card.md / start_snapshot.md / 场景目录
2. **不需要**5个物理锚点——scene_state.yaml 的空间定义中追记最多2个锚点
3. **不需要**道具清单——不允许在过渡空间中与物品交互
4. **允许**在过渡空间中遇到焦外角色——触发 §焦外→焦内主动接近协议
5. 过渡空间叙事长度不超过此处原始文本字数的1/3
6. 结束时必须落到正式场景。不能在过渡空间中停留超过一轮的叙事焦点

## 焦外→焦内主动接近协议

**触发条件：** 焦点角色移动到焦外角色所在空间位置（非焦外角色移动到焦点）。

**流程：**
1. 该焦外角色「活跃中」标记 `INTERRUPTED`
2. 读取其「已完成」记录（数据已在数据就绪检查阶段获取或按需补读）
3. 进入正常交互
4. 焦点离开后新建「活跃中」记录（原记录加时间戳保留）

**与普通揭示的区别：** 普通揭示是「结果被感知」（被动），主动接近是「走到了面前」（主动），开启完整场景级交互。

## 焦外背景更新原则

**对象**：焦外 = 不在当前焦点场景、但在世界中的角色（焦内=on-screen·焦外=off-screen）。焦点叙事是主体·焦外只做轻量状态增量。

**每轮检查相关焦外**（廉价·不数轮次）：同空间、Pending Action 窗口临近/到期、物理位移或状态变化、休眠/未推进 CT 对抗方、用户关注——据此每轮重判定焦外集合·不沿用上轮（集合 = 调度单.焦外（含循环预设）∪ ④自推演结果）。

**焦外维护分两层（关键·防丢失/防过度）**：
- **④角色层 → CHAR_state（主观状态·持续维护）**：角色是活的存在，其主观状态（位置/情绪/决策/计划/行动·自身视角）每轮经④自推演更新——焦外角色一样感知现场与冲突并作出反应；循环角色=轻量推演（decision.当前计划 已物化自 LOOPS·按日程推进＋感知过滤）。**角色仍活着·不冻结**。
- **⑤场记层 → pending_actions（有价值的客观事实·筛相关记）**：只记**有价值**的焦外客观事实（位移/状态变化/关系或冲突推进/临近揭示/窗口到期/用户关注）。「有价值」→ 记 pending_actions（标可揭示）；「无价值」→ 不记（记录静默·非角色冻结）。

**守则**：焦外推进=状态增量·不展开叙事；焦外描写可降频·检查不可降频（降篇幅·不降频率）。

**冲突升级**：休眠/未推进 CT 对抗方——①戏剧家据焦外动作推进冲突；⑤场记记焦外行动事实（场景级 pending_actions·可揭示）；是否值得进画面→③导演判定（§焦外→焦内协议）。

## 焦外行动的揭示原则（作家）

当叙事焦点切换到一个曾处于焦外的角色时：
1. 读取当前焦点场景的 `pending_actions` 中该角色的「已完成」行动记录
2. 这些行动的「结果」是被决定的——但角色「为什么这样做」的动机可以被叙事重新解读
3. 焦外行动的结果不能在同一场景中被重复揭示——揭示一次即锁定

## 存档/读档

统一通过 `snap.py` 完成。**save 全量备份**（动态状态 + CHAR_state + scenes/ 全目录）；**load 差异恢复**（存档有→覆盖；磁盘有而存档无→移入 `archive/scenes/` 保留不删；废弃 .active 自动归档）。**load 为破坏性操作：覆盖当前世界状态（自动备份 _before_）——交互提示确认 / 非交互加 `--force`**。**焦点场景唯一权威源 = world_state.yaml 顶层 `焦点场景`**。用户未指定存档名时，自动生成「r<轮次>-<场景目录名>-时间戳」（r 前缀便于按轮次识别快照）。**回退是低频例外**：快照恢复（snap load）+ 手工重建协议（references/rollback.md）——回退不走 write-raw、yaml 字符串字段禁行删、回退后必做残留扫描+validate。

## 状态校验（必做——触发：读档后 / 跨 Session 恢复后 / 用户要求检查状态 / 叙事重启前）

1. **格式（脚本可查）：** `worldctl.py {世界名} validate`——YAML 报错 / 引用警告（world_state.焦点场景↔INDEX ACTIVE↔场景目录、CHAR_state↔.md、CT-XX 键）
2. **内容（语义——脚本查不了，三步核对）：**
   **原理：** 内容错误 = 副本分歧（同一事实各处说法不同）+ 副本缺失（事实发生但无状态副本）。四根源覆盖分歧；缺失必须「从事实找副本」反向核对。按序执行：
   **① 提取：** 读 scene_state.场景时间线 + 最近 3-5 轮 narrative 归档 → 列出本时段关键事件（命名/关系确立/威胁/承诺/异常信号/直觉）。
   **② 对照：** 逐事件找副本——
      - 命名/身份变更 → CHAR_state.名字 + 记忆锚点？
      - 威胁/倒计时 → 外部倒计时/全局标记/CT 节拍？
      - 关系确立/变化 → CHAR_state.人际动态（当前全貌）+ 记忆锚点（原因/定性）？
      - 高刺激事件/异常/直觉 → 记忆锚点（yaml 列表元素·`轮次/时间/对象/内容`·轮次=元数据=回退裁剪基准）？
      - 事件序 → world_state 时间线(粗) + scene_state 场景时间线(细)？
      副本说法不一致 → 按四根源修：① 冗余分歧（位置/状态/名字各处一致？）② 事实过期（新事实没同步？紧迫度=休眠 还当活跃？倒计时到期没移除？CT 节拍停在已过去的时段？）③ 引用悬空（指针指向存在对象？）④ 数值非法（枚举内？CT 跳号？）。
      语义字段有歧义（如命名方向）→ 引用叙事原文复核——推断依据=叙事原文，不是压缩摘要。
   **专项一·CT 死条目（高频·显式查）：** conflicts 中存在 `状态: 已归档/已完成` 标记的 CT → 整条移除（keys.md：生命周期到期=从 conflicts 移除该 CT 条目，禁止留「已归档但相位=推进中」的矛盾条目）；CT 已完成但仍在 conflicts（对照时间线/相位停滞/紧迫度=休眠且无复活依据）→ 标记移除。移除用 `worldctl.py delete`。
   **专项二·档位表述一致性：** CT 描述/对抗双方/CHAR_state 核心状态/情绪/行动卡与连续行动轨迹中的自主性档位措辞（觉醒/漂移/清醒对抗/记忆碎片渗透等）与 CHAR_state.自主性 字段一致？档位字段为权威，不一致 → 修到与字段一致（禁止叙事/冲突字段给角色"升档"而状态字段未动）。
   **③ 修复：** 缺副本 → 补；副本矛盾 → 按四根源修（write-raw / delete / edit_file）→ 重新 validate 通过 → 才开写。禁止带着坏文件推进叙事。
   **体检经验：** 时间线缺口（顶层缺粗粒度/场景缺细粒度）、CT 节拍停在已过去时段、可选键缺失（如 CT.描述）是高频问题——对照时优先盯这三类。
