# WorldSim — 键表与写语义参考（keys.md）

> **本文件 = 全部状态文件的键表/视角规则/写语义明细。** 行为指令（怎么做）在 SKILL.md（编排）+ references/phase_*.md（阶段规则·阶段开始前必读），数据格式（查什么/写到哪）在此查。
> 写字段不确定时来此查路径和值类型；不逐轮加载。

## 记忆写语义总则（事件/状态二分·决策归戏剧家，场记机械落地）

写字段前先问：**这条是「事件」还是「状态」？**
- **事件**（发生了什么/变了什么/为什么/认知判断的原因）→ **追加进 `记忆锚点`**（###APPEND:，**yaml 列表元素**：`- 轮次: N` / `  时间: 第X日（+时刻可选）` / `  对象: 记忆核心人物` / `  内容: 以对象为主语的事实结果 ➔ 以角色为主语的主观定性`；**`轮次`=元数据（系统层·硬性·永不模糊/永不入叙事——回退裁剪基准：与 start_snapshot 开场轮次对照，轮次≥开场轮次的锚点是开场后产生的，场景重置时删除）**；`时间`=叙事时间（重置时按联动表可模糊为「碎片」）；对象=记忆核心人物（对方行为/话语触发者，纯自身行动才标「自身」——「我」开头≠对象是自身）；内容=角色=本文件角色即定性主语，禁止用他/她指代任何角色——一律用人名（群体/固定词「他们/她们/他人」除外））
- **状态**（此刻是什么样）→ **覆盖写状态字段**（###KEY:，写前 read 旧值，全量重写当前全貌）
- 禁止把历史塞进状态字段，也禁止把状态当历史追加。
- 记忆锚点的覆盖替换只在有依据时合法（记忆修正/抹除/压缩/循环重置/叙事重构）——无意识全量覆盖是 bug；有依据的替换是故事的一部分。
- **记忆分层**：短期=连续行动轨迹（角色时间线·不裁剪·复盘压缩）；长期=记忆锚点（跨轮保留·唯一历史仓库）。narrative 每轮被覆盖归档、不在加载清单——叙事文件不是角色的记忆，记忆锚点才是。**回忆细节反查（可选增强）：** 记忆锚点的 `轮次` 字段 = 索引键——需要补充某条记忆的叙事细节时，按 `轮次` 反查焦点场景目录下 `narrative.r{轮次}.*.md` 归档原文（`write_narrative.py` 轮转自动带轮次号；无轮次号归档=纯时间戳，可配合场景时间线定位）。反查是回忆素材，不改变创作依赖（叙事文件不参与创作数据）。

## CHAR_{name}_state.yaml

> **命名规则（硬性）：** 角色名含空格时文件名保留空格——`CHAR_Maeve Millay_state.yaml`。禁止用下划线替换空格。所有角色状态文件必须以 `_state.yaml` 结尾（含 Guest：`CHAR_Guest_state.yaml`）。写入时的 key 必须与文件名完全一致。

> **视角规则（本文件全局默认·所有字段适用）：** CHAR_state = 该角色的**主观状态文件**——默认角色主观视角，隐藏主语 = 本角色「我」。禁止用第三人称（他/她）指代本角色；**指代任何其他角色一律用具体人名，禁止用「他/她」代词——状态文件跨轮长期存储，代词会失去先行词**（「他们/她们/他人」等群体/固定词除外）。禁止全知视角——「Guest不知道/Clementine不知道」类叙述者视角禁止；只写「我」感知边界内的内容。认知判断的原因进记忆锚点、结果进档位字段。

**键表（写语义三分：🔁覆盖=当前快照｜➕追加=历史累积｜🪟窗口=脚本自动裁剪）：**

| 键 | 值类型 | 说明 | 写语义 |
|----|--------|------|--------|

**更新触发：** 每轮 Post-hoc（叙事写完后）| 场景切换 | 焦外揭示。角色批中，凡 ###ACTION 行动卡出现的角色必须在同批 CHAR_state 更新；调度单点名的焦内背景/焦外角色一律经④自推演后在同批更新 CHAR_state（无新发展=轻量刷新·见 phase_actor 焦外两步）——`###META` 的 `角色覆盖:` 标 `更新`，在轨循环角色标 `更新(在轨·轻量)`。是否变化由角色自己推演得出。

**特殊规则：**
- **极端事件覆盖：** 本轮涉及暴力侵犯/强制/入侵时，人际动态中该对象的档位不写入档位变化——标记为「待重建」。待叙事中角色开始修复关系时移除标记，档位从「中立」开始重建
- **不存在则创建：** 若角色 CHAR_state.yaml 不存在 → 基于叙事中已呈现的角色信息创建基础文件
- **自动创建规则：** 角色出现在 scene_card 出场角色 / scene_state 出场角色 / 调度单（焦内活跃·焦外）但无对应 CHAR_.md 和 CHAR_state 时，场记在场景初始化阶段或该角色首次进入焦点叙事时自动创建。禁止在场景已运行多轮后才补创建
- **骨架物化规则：** CHAR_state 仅骨架（占位符未填充）→ 不可用于维护/记录——先按 CHAR_.md 基线 ＋ 当前时刻/LOOPS 位置物化（位置/核心状态/decision.当前计划）再进入④维护（见 scene_management §场景切换流程第6步 / phase_actor 焦外自推演）
- **状态文件补全规则：** 有 CHAR_.md 但无 CHAR_state 的角色——若进入焦点叙事或持有活跃焦外行动 → 必须创建 _state.yaml；仅作为设定参考 → 可只有 .md
- **身份变更规则：** 角色获得/失去名字、被命名、记忆恢复、关系确立属于状态质变，必须在当轮写入「名字」或「人际动态」。禁止只留在叙事文件里

## scene_state.yaml

**键表：**

| 键 | 值类型 | 说明 |
|----|--------|------|
| `核心状态` | 多行 prose | 叙事层当前状态 |
| `场景时间线` | yaml 列表 | 该场景已发生事件序列（细粒度·区别于 world_state 粗粒度时间线）。元素三子字段：`轮次`（系统层元数据·回退裁剪基准——与记忆锚点同构·永不模糊）/`时间`（HH:MM-HH:MM）/`事件`。默认追加（按 轮次+时间 查重） |
| `物理锚点` | 多行 prose | 编号列表，含材质/位置/特征/状态。可视参照物——相邻区域节点只作方位提及，不作驻留空间（进入其内部=触发场景切换主判据·见 scene_management §移动场景协议） |
| `道具` | yaml 列表 | 元素四子字段：`ID`（唯一·P+编号）/`名称`/`位置`/`状态`——ID 唯一·validate 查重 |
| `关键场景信息` | 多行 prose | 线索列表，含物理描述+解读方向。追加为主，超出 ≤10KB 时压缩旧线索 |
| `出场角色摘要` | 多行 prose | 角色名/位置/关键姿态（可含「（焦外）」边缘观察者——有实质观察/行动者；纯背景焦外角色不写入） |

**更新触发：** 每轮 Post-hoc | 场景冻结（场景切换时锁存终态）

**落点（硬性·先于更新规则）：** scene_state.yaml 位于当前焦点场景目录——写入目标 = world_state.焦点场景 指向的场景目录。**写前必问：焦点场景 = 本叙事所在场景吗？** 不等 → 先走 §场景切换流程（同地点新时间区间也是新场景）更新焦点场景，再写 scene_state。漏查会把本场景事件写进旧场景文件，污染两个场景。

**更新规则：**
- 每轮时间推进/事件发生 → **追加**到 `场景时间线`（###APPEND:·yaml 列表元素：轮次/时间/事件·按 轮次+时间 查重）
- 道具位置/状态变化 → 更新 `道具` 表格
- POV 角色通过观察/对话/推理获得的新信息 → **追加**到 `关键场景信息`（###APPEND:；超出 ≤10KB 时压缩旧线索）
- 每项线索包含：物理描述 + 戏剧性解读方向（可选）

**特殊规则：** 禁止线索只留在 narrative.md 而不注册；≤10KB，超出压缩旧线索；**场景切换冻结：** 旧场景最终状态写入后锁存；`场景时间线` 提炼为 world_state 时间线中的粗粒度摘要。

**时间系：** 每轮 narrative 推进后，`时间.具体时间` = 旧值 + 本轮经过时长。方向只增不减。**写入前必做（场记）：对比旧 `时间.基准时间`——跨天/跨区间 → 先执行 §场景切换再写入；未跨 → 正常写入。**（跨天判定以日期字符串为准，独立于重置执行）

**倒计时协议（确立即登记）：** 倒计时 = 「将来某时到期·到期有后果」的事件在世界层的登记。事件确立即登记，到期即移除；周期事件（如每日重置）到期后自动重建下一期。登记触发（任一满足即登记）：① 事件确立 ② 感知出现 ③ 外部导入。**周期机制初始登记（循环/重置/契约/期限类周期机制·周期不一定是每日）：** 世界启动/会话恢复时登记为周期倒计时（剩余时间=距下一到期点·**重置类须含 `到期时刻` 精确字段**），此后每轮走表，到期执行后果并重建下一期——见 session_recovery.md §第二章启动世界·循环机制核对。**到期时刻权威源（硬性·防采样错位）**：SETTING「世界倒计时」显式声明 > 全体在轨角色 LOOPS 共同循环边界（醒转时刻=新循环开始）；**禁取单角色班次结束/入睡时刻当世界重置点**（实例：Angela 班次 22:00 结束≠世界重置·世界锚点=每日 06:00 醒转；单角色中途回收=事件触发 reset-cycle --asset）。
**重置类周期（循环世界）执行=机械管道：** write-raw 写 `world_state.时间.具体时间` 越过 `到期时刻` 且循环角色无覆盖当前日期的 `重置记录` → **该字段硬性顶回**（`[ERR] 重置未执行`）；执行用 `worldctl.py reset-cycle`（一键机械重置全员+登记+重建下一期+保留候选清单·见 commands.md）。走表：剩余时间随叙事时间推进递减 → 感知者（判定=自主性档位+认知边界）的 CT/压力随剩余时间缩短升级（≤30分钟联动）；未感知者照常运行。到期：执行后果 → 移除。字段约束：剩余时间只放数值；说明 ≤80 字；登记时标注「感知者」——倒计时是世界层字段，不自动产生冲突/压力，只有感知者产生 CT/压力反应。

**全局标记：**
- **什么时候写**（事件轮 Post-hoc）：世界级事件产生可定论结论、且结论尚未被时间线吸收时写入。
- **写什么**：结论性状态，≤60字，禁止叙事；角色个人状态禁止写入。标记名用中性名词（如 `Mariposa-抢劫`），不用时态短语（如 `Mariposa-抢劫进行中`）。
- **什么时候删**（每轮 Post-hoc 检查）：① 事件已进时间线 → 删；② 超2轮未进时间线 → 先合并后删，不留悬挂。空时保持 `{}`。
- **读（消费管道·硬性）：** 全局标记 = 世界层结论，**不直接进角色状态、不直接驱动角色反应**。读取路径：戏剧家见全局标记 → 按统一角色管理五层模型**逐角色检查感知**（认知边界 + 自主性档位）→ **感知者**更新 CHAR_state，未感知者不动。**标记存在本身 ≠ 全员压力。**

**世界事件生命周期（统一管道——同一世界事件在多个机制中承载，按序推进，禁止各自为政）：**

```text
① 法则常驻    —— SETTING 核心高压法则（每轮必查）：作用于全体，但压力逐角色感知过滤
② 倒计时登记  —— 事件确立 → 登记外部倒计时（周期事件到期移除后自动重建）→ 感知者 CT 推进（未感知者不产生压力）
③ 事件发生    —— 到期 → 执行机制（记忆重置联动表/事件结果落地）→ 移除倒计时（禁止累积）；**检查点=⑤场记世界收尾走表时（每轮·硬性）——周期重置倒计时越过到期点即触发 loop_machinery §4 重置联动表（周期覆盖的循环角色全员执行·机械管道：write-raw audit ④b 顶回+reset-cycle），不靠轮询记忆**
④ 结论落标    —— 事件产生可定论结论且未进时间线 → 写全局标记（≤60字·中性名词）
⑤ 反应消化    —— 戏剧家逐角色检查感知 → 感知者 CHAR_state 更新（锚点/压力/情绪/信念）
⑥ 标记退役    —— 事件已进时间线 → 删全局标记（不留悬挂·空时保持 {}）
```

**贯穿原则：机制执行全员化，心理压力感知者化。** 世界事件对全体角色客观发生，但冲突与压力只发生在感知者身上——两者之间隔着一道认知边界闸门。

**时间线：** 世界级粗粒度索引（每场景一条摘要·≤3 转折点·每条 ≤120 字）。默认追加：新转折点 → ###APPEND: 追加；压缩重写仅在 validate 告警后（条目≤10 / 单场景≤3 / 总字数≤2500 超限）→ ###KEY: 覆盖（先读旧值→压缩合并→补新）。写前先问：这是转折点还是明细？——转折点（命名/关系确立/威胁/重大事件）→ 入时间线；明细（对话/动作/过程）→ 写 scene_state 场景时间线。单条 ≤120 字粗粒度短语，事件内部用「，」/「→」，禁止用「·」分隔细节。

**特殊规则：** 初始写入：场景创建时从 INDEX 行和 scene_card 元数据填充。≤10 KB 总大小。**脚本校验线（validate 自动检查·LLM 不计数）：** 条目 ≤10 | 单场景 ≤3 转折点 | 总字数 ≤2500。若时间线无 → 初始化为 `{}`。

## 区域静态档案（regions/ · 可选增强层）

> **定位：** 区域静态设定（只读·世界初始设定·人工维护）。与 world_map 的区别：档案 = 设定源（上帝视角·t=0 快照），world_map = 探索进度（动态·从档案派生）。有 `regions/` 目录即激活本增强层；缺失不影响运行（validate 静默、snap 兼容）。模板：`templates/REGION.md`；规则详见 references/scene_management.md §区域静态档案。

**目录约定：** 每个节点一个 `{节点名}/REGION.md`——含子区域的节点与叶子节点同一结构（添加子节点 = 直接加子目录，零迁移）。目录名与 world_map 节点名对应；异名时 REGION.md `属性.对应节点` 写明映射。

**字段（只写静态事实）：** 属性（类型/安全等级/解禁条件/对应节点）/ 方位 / 相邻节点（连接静态权威）/ 环境与氛围 / 常驻NPC（CHAR 指针）/ 本地法则 / 叙事锚点（功能·不写进度）/ 子区域（子节点名+档案指针）。

**边界规则（硬性）：**
- **静态只读：** 档案**永不改**——布局变更（推倒墙/改建）是动态演进 → 写 scene_state + world_state 全局标记/时间线，档案保持初始设定
- **有档案 ≠ 已探索：** 档案预写是设定（同 SETTING.md 预写）；探索/解锁/认知归动态层——world_map 已探索区域按到达点亮，CHAR_state 已知地点 管角色认知
- **连接静态权威：** world_map 登记从档案复制连接，不新编
- **场景创建优先级链：** `--from` 已有场景（演进真相）→ 节点档案（初始基线）→ 从零注册。用档案生成基线后，场记对照 world_state 全局标记/时间线中该区域的已登记不可逆变更做增量覆盖再开写（档案=初始，全局标记=演进，覆盖后不会"墙又立起来了"）
- **单向派生对账：** validate 核对已登记 world_map 节点 vs 档案（类型一致/指针悬空）——派生对账不是双权威

**写入方式：** 一律用 `write`（YAML diff 递归合并·含单字段更新）——登记新区块与改单字段（如改备注）同走 write；**禁止 write-raw/append-raw/delete 点路径**（world_map 键名可含空格/点（如 `Westworld Park 1`、`Train No. 39`）·点路径与 shell 分词均不支持·write-raw 已机械拦截）。单字段更新示例（只给目标节点）：

```yaml
world_map:
  已探索区域:
    甜水镇:
      子区域:
        主街:
          备注: 发现水井
```

| `状态` | 枚举 | `待回收`/`已回收`/`废弃`（废弃=明确放弃·避免永久挂警告） |

**写语义：** ➕追加（`###APPEND: 伏笔`·结构化列表元素·按 `线索` 查重·重复追加跳过）。覆盖/清空走 `###KEY:`（列表文本/`[]`）。

**validate 检查（机械·LLM 零操作）：** 已回收且回收<种下 → 硬错（伏笔倒置）· 非法状态枚举 → 警告 · 已回收缺回收轮次 → 警告 · 待回收且当前轮次-种下>20 → 警告。

**与既有文件边界：** scene_state = 本轮场景出现什么（叙事层）· CT = 角色对抗节拍 · knowledge_index = 谁知道什么（认知）· 本文件 = 向读者承诺了什么（契约）。不参与循环重置（故事契约非角色认知）。

## conflicts.yaml

> **视角规则（本文件全局默认）：** conflicts = **全局上帝视角文件**——主语宾语默认写具体人名，**禁止用「我/你/他/她」代词**指代任何角色（引号内直接台词除外）。同一字段内人物首次出现写全名，后续可用短名，但必须是人名而非代词。理由：conflicts 跨轮长期存储、三方共用，代词会失去先行词。

**记录规则（写 CT 时执行）：**
- **记录**：冲突的结构张力——对抗双方、被争夺资源、当前对峙态势（空间/攻守/时机）与驱动（行动序列归 ###ACTION+连续行动轨迹·不复制进 CT）
- **不记录**：角色的记忆叙述副本——记忆内容由 CHAR_state 承载，conflicts 不复制；角色「为什么这么动」记驱动，记忆依据留在 CHAR_state 留痕
- **重置免疫**：CT 节拍不绑定会蒸发的内容（记忆文本）——重置后旧节拍要么仍成立（结构张力），要么按戏剧家 change set 改写结果更新

**键表：**

| 键 | 值类型 | 说明 |
|----|--------|------|
| `CT-{XX}.描述` | 短文本 | 一句话冲突主题（可选） |
| `CT-{XX}.施压方向` | 枚举 | 本轮对该 CT 的加压瞄准（①戏剧家唯一写·仅本轮推进池中的 CT 需标）：死局两难/防御踩爆/关系撕裂/不可逆代价/维持——瞄准声明·非结算字段非行动脚本；连续「维持」由脚本写入时机械比对磁盘旧值（连续两轮维持→警告）；停滞旗标在场时禁全维持（gate 核验）；③导演取材进 guidance 张力方向 |
| `CT-{XX}.对抗双方` | 短文本 | "动力方 vs 阻力方"（抽象方必须附显现机制：`{抽象方}（显现机制：代理人/机制载体/心理显影）`） |
| `CT-{XX}.被争夺资源` | 短文本 | {资源}·当前载体/持有者={谁/在哪}·双方动机（实体写持有者·抽象写载体） |
| `CT-{XX}.关系状态` | 多行 prose | 空间占位+攻守态势+未决时机（对峙动力学·升自 当前节拍 子字段） |
| `CT-{XX}.内部状态` | 多行 prose | 各角色独立：生理反应+认知判断+未抉择分叉 |
| `CT-{XX}.相位` | 枚举 | 推进中 ⏩ / 转折点 🔄 |
| `CT-{XX}.事件线引用` | 列表 | storyline_refs（如 `[SL-01]`·指向 storylines.事件线·validate 对账·悬空告警·①结算时维护） |
| `CT-{XX}.紧迫度` | 枚举 | 🔴/🟡/🟢/休眠 |
| `CT-{XX}.关联角色` | 列表 | 角色全名（逐行 `- 名字`·与 characters/ 档案名一致；写入格式见 write_protocol §①） |

**更新触发：** 每轮完整推进（事件线动作按当前拍选一：建线/推进/顶点停留或出线/换线/收束·废弃） | CT 节拍推进 | CT 生命周期变更（紧迫度冷却/升级/归档）

**更新规则：**
- 拆分：结构动作（建线/重规划/收束 close/废弃 clear）=②编剧 `###STORYLINE:`（写 storylines）；演出动作（指针 set/stay/advance）=③导演 `###BEAT:`（写 direction）——均由 write-raw 自动执行·LLM 不手动调用
- 每轮至少推进或注册一条 CT（①戏剧家推进池·硬性）；每轮推进该 CT 时必含资源状态变化——不更新=该 CT 本轮没推进
- 紧迫度变更 → 更新 `紧迫度`（每轮未推进冷却降级·客观紧急直接升级·激活重置）；生命周期到期 → 从 conflicts 移除该 CT 条目
- CT 不再含 当前节拍/下一个节拍(推荐)/角色反应/节拍表（已迁移字段——写入即硬拦·存量世界先 `worldctl.py <世界> migrate`）

## storylines.yaml（②编剧唯一写者·结构蓝图）

| `事件线.{SL-XX}.名称` | 短文本 | 一次跨轮展开的戏剧事件标识（建线 add·换线 rewrite·收束 close·废弃 clear·多条并行=多条） |
| `事件线.{SL-XX}.类型` | 短文本 | 对峙/追逃/营救/关系转折等 |

## pending_actions.yaml

**定位（facts 层·与 scene_state 互补）：**
- scene_state = 焦内（on-screen·当前场景）事实；pending_actions = 焦外（off-screen·与当前叙事**相关**·不在当前焦点空间的角色）事实——同一**事实层**的焦内/焦外。
- conflicts 是**戏剧层**（①·冲突张力视角：关系状态/内部状态/相位/紧迫度）——不与 pending_actions 互补（不同层·各写各的）。
- 焦外角色「做了什么/会怎么揭示」由**④角色层在轨**产出（写 CHAR_state）·**⑤场记**据④结果/CHAR_state 记录为本文件的焦外事实（**⑤不写 CHAR_state**·Single Writer）。
- **焦外事实是世界级的**（off-screen 世界持续）——文件挂在当前焦点场景（场景级），**场景切换按 `揭示场景` 迁移/归档**（揭示场景=新场景/仍相关→迁到新场景；=旧场景→留；已完成→保持，见 scene_management §场景切换流程第6步）·防「切换即断线」。

**键表：**

| 键 | 值类型 | 说明 |
|----|--------|------|
| `已完成.{PA-ID}.角色` | 短文本 | 角色名 |
| `已完成.{PA-ID}.时段` | 短文本 | "第1日13:00-13:15" |
| `已完成.{PA-ID}.行动` | 短文本 | 行动描述 |
| `已完成.{PA-ID}.结果` | 短文本 | 结果描述 |
| `已完成.{PA-ID}.揭示场景` | 短文本 | 场景ID或"待定" |
| `活跃中.{PA-ID}.角色` | 短文本 | 角色名 |
| `活跃中.{PA-ID}.启动场景` | 短文本 | 场景ID |
| `活跃中.{PA-ID}.行动` | 短文本 | 行动描述 |
| `活跃中.{PA-ID}.当前状态` | 短文本 | 当前状态+信号 |
| `活跃中.{PA-ID}.预计影响` | 短文本 | 影响预测 |
| `活跃中.{PA-ID}.揭示场景` | 短文本 | 场景ID或"待定"——指向实际揭示场景（③导演/⑤ 判定）·场景切换时按它迁移到新场景（见 scene_management §场景切换流程第6步） |

**更新触发：** 每轮 | 焦外行动揭示 | **场景切换（跨场景迁移/归档）**

**更新规则：**
- 叙事中已揭示的焦外行动 → 从 `活跃中` 移至 `已完成`，记入揭示场景
- conflicts 中标记的未揭示焦外推进 → 更新 `活跃中` 队列和状态
- 焦外角色物理状态变化 → CHAR_state 由**④角色层在轨**更新（⑤禁写 CHAR_state·Single Writer）·④在轨结果供⑤记本文件焦外事实
- **场景切换迁移**——焦点场景变化时：`活跃中` 条目按 `揭示场景` 归类迁移到对应场景 pending_actions（=新场景/仍相关→迁入；=旧场景→留旧场景归档；已完成→保持）；新场景 pending_actions = 旧场景迁移 ∪ 新场景④自推演派生。

**特殊规则：** ⑤只记焦外**行动事实**（从④结果/CHAR_state 派生·**不写 CHAR_state**）；焦外角色状态（含变化）由④在轨写 CHAR_state——禁止⑤绕过④改角色状态。
