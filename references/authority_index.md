# 元信息归属表（authority_index.md）

> **用途：** 规则文件**维护期**查表——改动 `SKILL.md` / `references/phase_*.md` / `references/*.md` 前先查本表。
> **不参与运行：** 本文件不在任何阶段的读取清单内，运行期不加载。
> **与 `runtime_scheduler.md` §3 的分工：** 该表管「**调度主题** → 归属文件」（运行期查表）；本表管「**元信息** → 唯一权威位」（维护期查表）。两者不重叠。

## 为什么需要本表

元信息需要被多个文件引用。**只要在 N 处各写一份，就必然在 N-1 处出问题**——本项目已实测 15 处此类不一致（编号错引、阈值冲突、清单漏项、命令名不统一、悬空引用）。

三条规则：

1. **单点承载** — 每项元信息只在**一个**权威位完整定义
2. **引名不引号** — 其他位置引用时**写名称，不写编号**；必须写编号时**带文件归属**
3. **数值不复制** — 阈值与清单不在引用处重复具体值，只写指针

> **为什么必须限定：** `Dn` 前缀被 `phase_dramatist` / `phase_storyliner` / `phase_director` / `actor_decision` 四个文件共用，同名不同义（如 `D2` 在前者是「对峙态势」、在后者是「变质判定」）。裸编号读者无法判定空间——实测已致 5 处错引 + 1 处幽灵名。
>
> **两种引用形式的取舍：** 限定编号（`<文件> Dn`）短、可跳转、与库内既有惯例一致（如 `phase_storyliner.md D1–D6`），解决**歧义**；引名（`<文件>「名称」`）额外解决**重排**（编号互换时名字不变）。当前采用限定编号；是否进一步转引名见后续评估。

## 维护纪律

- **新增元信息前先查本表** — 已有权威位则补进该位，不另立第二处
- **改动元信息后扫本表** — 确认引用处是否需同步（引名形式不随编号变化，通常无需改）
- **本表可机检** — 运行 `python3 scripts/lint_docs.py`（维护期·非运行期·只报告不改）检查三类：**裸编号**（`Dn` 跨文件引用未带文件名/阶段限定）、**悬空引用**（`X.md「Y」` 的目标文件或锚点文本不存在）、**命令名**（`python <脚本>` 应为 `python3`）。**阈值多值**一项待本表扩为阈值登记表后再加。
