# knowledge_index.yaml — 知情边界追踪索引

## 定位

**是什么：** `worlds/{世界}/states/knowledge_index.yaml` = 世界**知情边界**的事实追踪索引（纯数据文件·可选）。收录「谁知道了什么、谁知道谁不知道」——这是整个状态体系唯一没有承载的事实维度。

**双重用途：**
- **运行视角（六阶段）**：认知边界闸门的机械辅助——设计/填充/落盘前查「这个角色知道什么」
- **审计视角**：一致性检查清单——session 恢复和 /audit 时按索引核对状态文件

**三条原则：**
1. **可选**——短世界不建，长世界或重视一致性才建。不建 = audit 少查一页，不影响运行
2. **日常零负担**——收录只在关键节点·检查只在等待窗口·每轮推进不碰
3. **删除不激进**——不确定就留（删晚无害·删早有害）

## 收录标准（场记写什么）

**触发（问题链·与场记既有判断重叠）：**
> ① 这个事实有知情差异吗？（有人不知道/未被看见/是秘密）
> ② 事后还会被引用吗？（后续轮次会再提到它）
> ①②都是「是」→ 收录一条。

**不收录：** 已公开无差异的事实（scene_state/world_state 时间线已覆盖）· 本轮瞬态 · 主观感受（记忆锚点职责）· 世界级状态（world_state 已承载）。

**更新时机 = 关键节点**（事实产生知情差异时/事实变化时），不做逐轮同步。关键节点本身是事实变化点，场记在那里顺手更新，不额外负担。

## 加载与使用（六阶段·认知边界闸门）

**加载：** 恢复时「有则读一次」（与 CROSS_NARRATIVES.md 同模式），上下文已有则跳过，不逐轮加载。

**使用（认知边界闸门 = 六阶段共用硬性约束·SKILL.md 通用约束）：**

| 角色 | 使用方式 |
|------|---------|
| 戏剧家 | 设计行为/台词/反应前查：这个角色知道 X 吗？——索引给出「X 被谁知道」总览（设计侧） |
| 作家 | 写台词/动作前查：POV 角色知道 X 吗？——索引 + 指向的状态文件核对（填充侧） |
| 角色 | 写记忆锚点/状态前查：这个事实该进这个角色的记忆吗？（落盘侧·CHAR_state 唯一写者） |

**硬性规则：索引是提示不是权威**——需要真相时读 `记录` 指向的状态文件原文，不信任索引的「事实」一栏为最新。索引更新滞后于状态文件时以状态文件为准。

## 检查流程

**触发（两个时机）：**
- 启动世界（session_recovery.md 第二章 加载序列 Step 7 知情边界核对）
- /audit（三合一流程）

**执行者：** 独立审计者视角（复用「角色转变声明」——非本轮决策者）。

**方法：** 逐条按 `记录` 指针读状态文件 → 比对事实的知情状态与索引是否一致：
- 一致 → 通过
- 矛盾 → 能定位的修复（补写状态文件·场记执行）；**循环重置导致的失效条目直接删除**（知情边界已抹平·检查对象不存在）；定位不了的标记「存疑」留给用户

**能查出：** 多文件副本互相矛盾（漏同步/知情边界漂移）。**查不出：** 共同漂移（所有文件一起错）· 当轮幻觉——只治跨轮慢性病。

## 清理标准

**时机：** 检查完成后顺手——刚读完所有文件·信息最充分·判断成本最低。

**判断（问题链·不确定就留）：**
> ① 事实还处于「有知情差异」状态吗？
> ② 已公开（秘密说出/全员目睹）/ 已落定（最终态已写入权威文件）/ 循环重置抹平 → 删；仍隐藏/仍在延续 → 留。

**执行：** audit 报告列出「建议删除」→ 场记从索引删除对应条目（普通文件操作）。

## 生命周期

```
收录（关键节点·场记顺手·30秒）
  → 加载（恢复时·六阶段上下文）
  → 使用（设计/填充/落盘前查·认知边界闸门）
  → 检查（session恢复 + /audit·独立审计视角·按指针比对）
  → 清理（检查后顺手·不确定就留·循环重置失效条目直接删）
```
