# foreshadow.yaml — 伏笔登记（故事契约层）

## 定位

**是什么：** `worlds/{世界}/states/foreshadow.yaml` = 世界**伏笔闭环**的追踪索引（纯数据文件·可选）。收录「故事向读者承诺了什么、是否已回收」——与 knowledge_index（谁知道什么·认知边界）正交，这是**叙事契约层**。

**借鉴来源：** story-skills 的 Promises/Payoffs 机制，但按实时交互叙事裁剪：1 个聚合文件（非一伏笔一文件）、4+1 字段（非 8 字段）、触发式写入（非每章维护）、检查只在 validate/audit。

**双重用途：**
- **运行视角**：戏剧家参考。运行时感知靠 scene_state 线索/CT（已在读）
- **审计视角**：一致性检查清单——validate 机械检查（轮次倒置/超时/枚举）+ /audit 时 LLM 人工核对时间错位

## 收录标准（场记/戏剧家写什么）

**触发（关键节点·与场记三问①/收尾自查①既有「道具线索→scene_state」检查同点）：**
> ① 新伏笔种下时（叙事首次埋下一条将跨轮次兑现的线索）→ 登记一条
> ② 伏笔回收时（线索兑现/揭晓）→ 更新 回收+状态

**不收录：** 本轮瞬态（scene_state 已覆盖）· 角色认知差异（knowledge_index 职责）· 角色间冲突（CT 职责）· 角色主观感受（记忆锚点职责）。

## 字段与写语义

| 字段 | 说明 |
|------|------|
| `线索` | 伏笔内容（≤40 字） |
| `种下` | 种下时全局轮次（world_state.轮次·单调递增） |
| `时间` | 种下时叙事时间（world_state.时间.具体时间·供 /audit 人工核对时间错位·不程序比较） |
| `回收` | 回收时全局轮次（待回收/废弃留空） |
| `状态` | 枚举：`待回收`/`已回收`/`废弃`（废弃=明确放弃·避免永久挂警告） |

写入：`###FILE: foreshadow` + `###APPEND: 伏笔`（结构化列表元素·按 `线索` 查重）。覆盖/清空走 KEY（列表文本/`[]`）。**触发式——大多数轮次不碰。**

## 检查规则（worldctl.py validate·只在 /audit 与日常 validate 时跑）

| 规则 | 级别 |
|------|------|
| 已回收 且 回收 < 种下（伏笔倒置） | 硬错 |
| 非法状态枚举 | 警告 |
| 已回收但缺 回收 轮次 | 警告 |
| 待回收 且 当前轮次-种下 > 20 | 警告（建议回收或废弃） |

`时间` 字段不程序比较——时间错位（种下第3日傍晚·到第7日未回收）由 /audit 时 LLM 人工核对。

## 边界与生命周期

- **不参与循环重置**：伏笔是故事契约（读者视角），不是角色认知——角色记忆重置不清空伏笔
- **删除**：不设专门删除机制（低频·误登记走 KEY 重写·闭环条目保留防重复种下）。确需清理 → 文件级编辑（低频·audit 时顺手）
- **可选**：短世界不建。不建 = validate 少查一页，不影响运行

## 加载

戏剧家设计长线剧情时可按需 read 核对已埋伏笔（避免重复种下同一条）。
