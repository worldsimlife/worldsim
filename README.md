# WorldSim — Where Worlds Come to Life

> 世界模拟器 · 故事引擎 · 实时戏剧 · 角色扮演

> WorldSim 不只是角色扮演，它是一个会呼吸的世界：角色有血有肉，在冲突中做出取舍；无人注视的角落，命运也在沉浮。你走进去，就是故事中人。
> 给深度角色扮演玩家与戏剧创作者。

**English version: [README.en.md](README.en.md)**

## 这是什么

WorldSim 是一个 **Agent Skill（技能包）**——它不是一个独立软件，而是装进 AI 客户端、让 AI 学会「运转一个真实世界」的能力包。

安装之后，你的 AI 助手不再只是一个会聊天的模型：它会变成一台**世界模拟器**。你给它一句话，它让一个世界真实地运转起来，讲述鲜活的故事。

运转的意思是——角色有自己的欲望、恐惧和底线；你伤害过的角色会记得；你没看着的地方，故事也在发生；痛苦会在角色身上留下痕迹，痕迹累积，角色会不可逆地改变。

**支持导入 SillyTavern 角色卡**：把现成的角色卡（PNG/JSON）直接导入，自动生成正式角色档案，无需从零手写。

**这个世界的主角是角色，不是玩家。** 你也在其中——你是那个会让角色记住、或遗忘的人。你的每一个决定，都是一颗埋进这个世界的种子——之后发生的一切，是它自己的演化。

## 设计哲学

> **给评审者（修改 SKILL.md 与 references/phase_*.md 前必读）：** 引擎规则繁多，因为每一轮都在对抗 LLM 的默认行为——顺从（和解/退让/快速收场）。规则多是战争痕迹，不是冗余。判断规则去留的标准：是否在对抗顺从？是否可代码化？本文件所有规则都服务于本节的「设计哲学」（活起来 + 戏剧化四爆破工程）；与设计哲学冲突的修改，即使局部合理也应否决。

### 活起来：先有真实的人

让故事人物活起来，核心在于**以过往经历与心理防御塑造性格裂缝，并赋予其超越大纲控制的自主逻辑**。当人物被内心的欲望与恐惧、信念与矛盾撕扯，在危机中做出符合自身本能和价值观的选择时——他便不再是作者操纵的傀儡，而成为一个真正拥有生命的人。

### 戏剧化：再让真实的人在压力下流血

只有真实感，故事会沦为「平淡的生活流水账」。戏剧性（Drama）的本质，是**压力下的冲突与选择**。

如果说「鲜活的人物」是性能强悍的跑车，那么「戏剧性」就是精心铺设的赛道——障碍、急转弯与断崖。关键不在于外部事件有多热闹，而在于**用外部结构精准「踩爆」内部变量**：外部事件以不可逆的态势，逼迫人物在自己的内核里进行痛苦的自相残杀。

四个爆破工程：

1. **制造死局两难**（Dilemma）——只给「保住 A 就要毁灭 B」的选择，让欲望与恐惧、价值底线硬碰硬。读者看到的不是「她去救人了」，而是「她忍着剧痛、撕裂尊严去救人」。
2. **踩爆防御机制**（Defense Invalidation）——当众剥夺人物的保护壳，逼她以最脆弱、最赤裸的本态面对危机。毒舌者的冷漠被绝对信任击穿，强硬者的防线被温柔拆除。
3. **升级信息差与阵营撕裂**（Relationship Interruption）——让互相深爱的人因各自不同的核心信念，在同一个事件中走向对立面。「双向的善意导致的悲剧」，是最高级的戏剧性。
4. **推动不可逆的代价**（Irreversible Choice）——给决策加上高压计时器，选择之后必须永恒失去某种东西：一个秘密被曝光、一份信任彻底破裂、一个重要物件被毁。

> 这套引擎的一切规则（人格系统、冲突节拍、防御与底线、外部倒计时）都在为这两个词服务：**活起来**，然后**在压力下选择**。

为什么需要这么多规则？——因为 AI 的默认本能是顺从：快速和解、退让、把故事平安收场。WorldSim 的每一条规则都在对抗这种本能。规则多是战争痕迹，不是冗余：它们存在的意义，是把故事按在悬崖边。

## 你的故事会留下来

每一轮叙事，引擎都会把它记进当前场景的 `narrative.md`——甜水镇的故事落在甜水镇的 narrative，下一场戏落在下一场的 narrative。按时间顺序连起来，就是一部完整的小说：这个世界的编年史，从第一句台词写到最后一个句点。

想回顾？打开 `worlds/{世界名}/scenes/` 下对应场景目录，`narrative.md` 连同它的轮转归档就是全部文本——从第一章读到最后一章，一字不落。

也可以直接对 WorldSim 说一句「帮我把叙事整理成小说」——它会通读全部 narrative 归档，把编年史整理成一部完整的小说稿。

---

## 数据存储与隐私

每一轮叙事都会写入 `worlds/{世界名}/scenes/…/narrative.md` 并轮转归档；导入的 SillyTavern 角色卡仅作为临时素材用于生成角色档案，档案生成后即删除。所有数据都在本地磁盘——**请勿在故事中输入密码、机密或个人敏感信息**。删除 `worlds/{世界名}/` 目录即可彻底清除该世界全部记录（含叙事、状态与快照）。

---

## 世界数据存哪里（环境变量）

默认世界数据存放在 skill 目录内的 `worlds/`。想把它放到你自己的存储（独立磁盘 / 网络盘 / 容器卷），设置环境变量 **`WORLDSIM_WORLDS_DIR`** 指向你的目录即可——全部脚本（校验/写入/快照/重置/导入）经该变量解析世界路径；未设置时回退到 `{skill_dir}/worlds/`。skill 本体（SKILL.md / 脚本 / 模板）始终由脚本自身位置定位，**不可**被环境变量改变。

## 安装

WorldSim 目前通过两个渠道分发：**Clawhub**（推荐）与 **GitHub**。两者都是同一个 skill，选其一即可。

发布与版本历史见 [GitHub Releases](https://github.com/zhaowh/worldsim/releases)

### 能力声明

本 skill 为运转世界需要读写本地文件（世界档案、叙事记录、快照），并调用 `scripts/` 下的维护脚本（校验/写入/快照/重置/导入）。安装即视为同意这些本地文件操作。

### 方式一：从 Clawhub 安装（推荐）

[Clawhub 页面](https://clawhub.ai/zhaowh/skills/worldsim) · 依赖 OpenClaw CLI：

```sh
openclaw skills install @zhaowh/worldsim
```

### 方式二：从 GitHub 安装

```sh
git clone https://github.com/zhaowh/worldsim.git
```

把 `worldsim` 目录（或符号链接）放到你的客户端技能目录，例如 Codex / Claude Code 类的 `.codex/skills/` 或 `.claude/skills/` 下，确保最终路径为 `…/skills/worldsim/`。

### 环境要求

- **Python 3.10+** 与 **PyYAML**（世界状态读写引擎 `worldctl.py` 的运行时依赖）
- **sh**（POSIX shell，脚本工具链使用）
- 支持 Agent Skills 的客户端（OpenClaw / Codex / Claude Code 等）

## 怎么玩

### 三步开始

1. **创建世界** —— 对它说「创建世界 <名字>」，告诉它你想看什么样的世界。它帮你搭好世界观、角色档案、冲突种子——想偷懒就只给一句话，想打磨就陪它一起磨。**也可以在这一步直接说「导入角色卡 <文件>」**，并创建新世界。
2. **启动世界** —— 说「启动 <名字> 世界」。引擎物化一切，为你描绘世界入口，然后停在起点，等你开口。
3. **开口** —— 说出你要做的第一件事。故事从这一句开始，从此不会再完全回到原样。或者只说「继续剧情」，世界也会自己往下走。

### 从角色卡导入角色（SillyTavern / Chub.ai）

WorldSim 支持导入 **SillyTavern 兼容的角色卡**（`.png` 内嵌 JSON 或纯 `.json`）——把社区里现成的角色直接变成 WorldSim 角色档案，而不是从零手写。

**两个时机都可以：**
- **创建世界时** —— 说「创建世界 <名字>，并把 <角色卡.png> 里的角色放进去」
- **已有世界随时** —— 说「导入角色卡 <角色卡.png> 到 <世界名>」或 `/import-card <角色卡.png...>`

**导入怎么工作**：脚本机械提取角色卡全部内容（含世界观、开场白、备用开场白、知识库等）作为临时素材 → AI 通读并先做风险评估（发现提示注入/敏感/版权内容会先向你披露、经你确认后才继续）→ 按 WorldSim 角色档案结构综合生成正式档案，未提供的字段留空、装不下的信息收进「补充设定」区，尽量不丢；临时素材在档案生成后即删除。

### 你会慢慢发现的

- **角色不是 NPC。** 他们有执念，有欲望，有恐惧。你想推进的和解，可能要付出真实的代价；你背叛过的人，会记得你背叛过他。
- **代价是不可逆的。** 资源易主、关系破裂、控制权易手——失去的东西不会凭空回来。
- **你不在场的地方，世界也在运转。** 角落里的角色也在做选择，直到命运让你们相遇——到那时，一切都有迹可循。
- **你可以成为任何人。** 「切换到 Dolores」——从她的眼睛里醒来；「切换到游客」——回到自己身上，看世界因你的选择转向。
- **时间是你的。** 随时存档、读档，让同一个选择以两种方式去活；随时重开一场戏、重置整个世界，或开启不同的时间线。
- **循环世界也行。** 你甚至可以造一个每天重置的世界——然后看着某个人开始「记得」。

## 你会用到的话

| 你想做什么 | 说什么 |
|-----------|--------|
| 看看世界走到哪了（完整状态含暗处细节） | `/status` · `/status --full` |
| 看看暗处发酵的冲突 | `/conflicts` |
| 成为某个角色，用 TA 的眼睛活 | 「切换到 Dolores 视角」 |
| 切换 / 新建场景 | `/scene <ID>` · `/scene new <名>` |
| 场记同步（告诉引擎最新变化） | `/sync` |
| 存档 / 读档（读档前自动备份 _before_，可回滚） | `/save [名]` · `/load <名>` |
| 重开一场戏 | `/reset-scene [场景ID]` |
| 让世界重新开始 | `/reset` |
| 导入现成的角色卡 | `/import-card <角色卡.png...>` |
| 导演监视器（看引擎每一步决策） | `/loud` |
| 回到沉浸模式 | `/silent` |
| **觉察不对劲·审计引擎决策** | `/audit` |

> **审计**（`/audit`）：你觉得哪里不对劲时使用——引擎按六阶段清单（戏剧家D/编剧S/导演R/角色A/场记K/作家W）逐项核对世界状态与叙事，输出 PASS/FAIL + 证据（文件路径+字段原文），发现问题按修复流程处理。若审计反复发现同类违规（引擎老是不按规则执行、补丁无效）——建议换一个 agent 或 LLM model。

## 技术架构：单上下文六阶段管线

WorldSim 以单 LLM 单上下文为核心架构，与行业常见的 Multi-Agent（多智能体并发碰撞）架构——高成本、低密度的「蜂群式对话」——不同。它不是多个模型互相聊天，而是同一台引擎在同一上下文里按阶段分段执行，六个逻辑层顺序运行，共享同一份世界知识与会话历史：

1. **戏剧家（Dramatist）**——冲突引擎：扫描压力源，注册/推进/升级冲突（CT），制造死局与不可逆代价，把角色逼上悬崖
2. **编剧（Storyliner）**——结构引擎：故事弧线、事件线、拍序——把冲突编织成命运，把握宏观走向
3. **导演（Director）**——现场引擎：回判上轮实际演出结果，掌控当前拍的节奏、承接与转场——在最该爆裂的时候爆裂
4. **角色（Actor）**——生命层：NPC 基于人格动力/当前目标/行动状态/环境压力四层驱动自主决策并即兴行动——拥有独立于玩家的连续时间线，玩家可以打断它，但玩家不是它的起点
5. **场记（Script Supervisor）**——事实引擎：记录已经发生的事实，把每一轮活进档案——长会话上下文不漂移
6. **作家（Writer）**——叙事引擎：把用户刚刚经历的世界写成小说——让读者看到悬崖上那一跳

七个状态文件各只有一个权威写入者（Single Writer per State）；常态轮走轻量路径（条件跳过），重大变化才进重路径。为控制单轮认知负载，**规则按需加载**：SKILL.md 只保留编排与约束；六阶段详规（`references/phase_*.md`）在执行到该阶段时才读取——到该阶段再读、再决策、再生成。阶段之间以**产物交接 + 脚本闸门**为边界：每阶段产出自己的写入批次（首行 `###STAGE:`），过各自的 `gate <阶段> --check` 才进下一阶段；场记收尾跑 `round-check` 轮完整性检查；作家叙事过 W4 锚点核验后才输出，输出即回合终点。

**用戏剧思维替代模型堆叠**——质量来自剧本创作的纪律，而非模型数量：用低成本，达到超出预期的效果。
